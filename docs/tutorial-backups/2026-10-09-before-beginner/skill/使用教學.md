# 整體視覺 Skill 使用教學

更新：2026-10-09

給要用整體視覺方案製作網站的設計師。讀完會知道怎麼安裝、開案要準備什麼、每個確認點看什麼、怎麼下指令與給回饋，以及出問題時怎麼排除。

本文件只說明操作方式，不另立規則。流程與驗收以 [主 Skill](skills/visual-solution-immersive-director/SKILL.md) 為準；兩者有出入時以主 Skill 為準，並回報維護者修正本文件。

圖文版是同資料夾的 [使用教學.html](使用教學.html)，用瀏覽器開啟；兩份內容需同步更新。這兩份都是給人看的，AI 執行案件時讀的是主 Skill 與它的 references。

## 先看重點

- **只有一個入口**：`visual-solution-immersive-director`（整體視覺網站設計與製作）。設計、素材、切版與自查在同一個任務完成，不分派角色，也不會自動開多個 AI 代理。
- **你負責判斷，AI 負責做**：你提供資料、做五次確認與取捨；整理資料、提案、做素材、實作、實看與修正由 Skill 主動完成。不用先想好構圖、動畫或技術再來找它。
- **預設只做 2560×1280 桌機**：平板與手機（RWD）要另外提出才會做。
- **「好」只確認眼前看到的**：靜態視覺通過不代表動態通過，片段通過不代表整頁通過。
- **要交工程師轉 EVO**：先看 [第 14 節](#14靜態切版到-evo設計師實際怎麼用)，有開工指令、檔案分工示例與交付表。

## 1｜套件裡有什麼

| Skill | 用途 | 需要直接叫它嗎 |
|---|---|---|
| `visual-solution-immersive-director` | 整體視覺網站的唯一主入口：盤點、提案、動態分鏡、試做、首頁與內頁 | 要，所有案件從這裡開始 |
| `eagle-visual-solution-curator` | 把喜歡的網站、截圖或影片整理成可貼進 Eagle 的名稱、分類、標籤與備註 | 要收藏案例時 |
| `eagle` | 操作本機 Eagle 資源庫：搜尋、資料夾、標籤 | 通常不用，其他 Skill 需要時會讀；想直接搜 Eagle 也可以叫它 |
| `gsap-*`（8 支） | GSAP 動態的技術參考 | 不用，主 Skill 做動態時按需讀取 |

**適合**：以客戶既有品牌內容為主體，需要專屬構圖、影像整合與有目的互動的整體視覺網站；忠實重建指定來源；只取參考的某個特徵；同案的內頁延伸。

**不適合**：

- 高效方案案件：母版、流程與產圖管道都不同，請用高效方案的 Skill。
- 與整體視覺案件無關的一般切版或小幅 CSS 修改：直接請 AI 修改即可，不必啟動整套流程。
- 還沒有品牌母題與主視覺資產的「品牌賦能」案：先完成品牌概念與專屬素材，再回來做網站。

## 2｜安裝

看你用哪個工具：**Claude Code 用 Plugin**，**Codex 用安裝程式**。兩種都用的人，各自裝一次。

repo 是私人的，GitHub 帳號要先請維護者加為協作者。只有用到 Eagle 時才需要：Eagle 已開啟並啟用 Eagle MCP 外掛（本機 API，埠號 41596），以及 Node.js。

### A｜Claude Code：用 Plugin

不需要 Python，也不用自己 clone。每台電腦裝一次，之後透過 Plugin 更新；是否自動更新取決於下方的 auto-update 設定。

**安裝前：先讓電腦登入 GitHub（每台電腦一次）**

repo 是私人的，Plugin 安裝時會用電腦裡的 Git 去 GitHub 抓檔案。只在瀏覽器登入 GitHub 網站不夠，電腦裡的 Git 也要登入，否則安裝會失敗。

1. 把你的 GitHub 帳號給維護者（LIN），請他加你為協作者。到信箱收 GitHub 的邀請信，按 **Accept invitation** 接受。
2. 在 Claude Code 輸入下面這句，請它幫你登入：

   ```text
   幫我用 GitHub CLI 登入 GitHub，並設定好讓 git 可以存取私人 repo
   ```

   Claude Code 會安裝登入工具、打開瀏覽器，你在 GitHub 頁面按授權就完成。電腦還沒有 Git 時，它也會一併處理；需要電腦管理者密碼時由你自己輸入。

**安裝 Plugin**

1. 在 Claude Code 輸入，加入套件來源（只要做一次）：

   ```text
   /plugin marketplace add world-yingcen/Visual-Solution-Workflow
   ```

2. 安裝：

   ```text
   /plugin install visual-solution@visual-solution-workflow
   ```

   一次裝好主 Skill、8 支 GSAP、2 支 Eagle。

3. 重新開啟 Claude Code。Skill 名稱會多一段前綴 `visual-solution:`，例如主 Skill 是 `visual-solution:visual-solution-immersive-director`。

**開啟自動更新**：輸入 `/plugin` → Marketplaces → 選 `visual-solution-workflow` → 開啟 Enable auto-update。沒開的話，要手動輸入 `/plugin marketplace update visual-solution-workflow` 才會拿到新版。

**移除**：`/plugin uninstall visual-solution@visual-solution-workflow`。

**以前用安裝程式裝過的人**：先移除舊的，不然會出現兩份。到當初 clone 的 `skill/` 資料夾執行 `python3 install.py --status` 核對，再執行 `python3 install.py --uninstall`，然後照上面裝 Plugin。

### B｜Codex：用安裝程式

需要 Python 3.9 以上（終端機輸入 `python3 --version` 確認）與 Git。把 repo clone 到本機固定資料夾，每台電腦各一份，不放雲端硬碟；雲端硬碟不會幫你 `git pull`，兩台電腦同步同一個 `.git` 還會弄壞它。

1. clone 後進到 `skill/` 資料夾，指令都在這裡執行：

   ```bash
   git clone https://github.com/world-yingcen/Visual-Solution-Workflow.git
   cd Visual-Solution-Workflow/skill
   ```

2. 試跑，只列出會做什麼，不寫入任何檔案：

   ```bash
   python3 install.py --target ~/.codex/skills --dry-run
   ```

   應該看到 11 行 `[新增]`：主 Skill、8 支 GSAP、2 支 Eagle。

3. 正式安裝：

   ```bash
   python3 install.py --target ~/.codex/skills
   ```

   預設建立捷徑，指向 clone 的資料夾；Windows 無法建捷徑時會自動改用複製。

4. 檢查狀態：

   ```bash
   python3 install.py --target ~/.codex/skills --status
   ```

   每一支都顯示 `[正常]`，最後一行是「主 Skill 正常，可以使用。」就完成了。

5. 重新開啟 Codex。

**捷徑指向 clone 的資料夾**，所以資料夾放定位後不要搬、不要放雲端硬碟；搬走捷徑就斷了。Windows 用複製安裝的人，每次更新後要再跑一次安裝指令。請用安裝程式裝整包，不要只手動搬主 Skill 資料夾，否則會缺少 GSAP 技術參考。

不想用 Plugin 的 Claude Code 使用者，也可以照這段安裝，指令拿掉 `--target ~/.codex/skills` 即可（裝到 `~/.claude/skills`）。

**更新**：每次觸發主 Skill 時，會先依安裝紀錄核對來源與目標，再更新、確認同步並重讀規則。Codex 在套件的 skill/ 目錄執行 `python3 install.py --update --target ~/.codex/skills`；Claude Code 的安裝程式版本使用原本的目標。來源有未提交修改／分歧、沒有網路或權限時保留現況，使用現有版本並說明限制。維護套件本身時不自我更新。

複製安裝不能只看「已經是最新版」：AI 還需比較來源與安裝副本；確認沒有本機自訂差異後，必要時以同一來源、同一 target 執行 `--copy` 同步。沒有 git 的人向維護者取得新版分享包，再核對後複製安裝。Plugin 則使用自己的更新機制，不能把 auto-update 已開啟當成這次已取得新版的證據。

**移除**：先 `--status` 核對，再 `--uninstall`（記得加同樣的 `--target`）。只移除這支安裝程式裝過的項目，不動其他 Skill，也不刪套件資料夾本身。

## 3｜開案前準備

不必先把檔案重新命名或分類，集中到同一個案件資料夾即可。案件資料夾放在 Google 雲端硬碟的同步資料夾裡，公司和家裡都接得上，不用搬檔案；做完再推到 git。盤點與歸位由 Skill 處理，要搬移檔案前會先給你確認。

| 準備什麼 | 說明 |
|---|---|
| 客戶資料 | 網站製作 MEMO 與需求單放線上文件的連結（例如一個 TXT 寫上連結），不放 PDF；另附訪談紀錄、產業背景、既有網站網址 |
| 品牌素材 | Logo、CIS 或品牌規範。沒有 CIS 也能開始，Skill 會先提建議與樣張給你判斷 |
| 內容與素材 | 已確認的文案與網站架構、圖片、影片、型錄。原始檔保留原件 |
| 不能改的部分 | 角色、產品外型、包裝、建築、主視覺、識別色與材質。先講清楚，Skill 只會加強呈現，不會重新設計 |
| 參考網站（選用） | 一定要說清楚用途，見下表 |

參考網站的用途決定整個案子走哪條路：

| 你的意思 | 建議說法 | Skill 的做法 |
|---|---|---|
| 照著做 | 「首頁照這個網站忠實重建，內容換成本案」 | 忠實重建：來源就是答案，不重新發想，逐項對照還原 |
| 只要某個特徵 | 「只取這個 Banner 的照片錯位疊層，其他原創」 | 指定特徵轉譯：列出要保留、要轉換、開放原創的部分 |
| 當作品質標準 | 「參考它的完成度，方向依品牌由你提案」 | 原創：參考只是證據，方向從本案品牌內容發展 |

只說「參考這個」時，Skill 會先整理可保留與可改的部分再跟你確認，不會自己決定怎麼混用。

## 4｜啟動與接續案件

### 在哪裡開

在 Claude Code 把工作資料夾設為雲端硬碟裡的案件資料夾；用終端機的話，先 `cd` 到案件資料夾再輸入 `claude`。在 Skill 套件資料夾（本 repo）裡，預設只維護 Skill 本身，要做案件必須明確說明。

### 第一句話

Claude Code 用 Plugin 安裝的，輸入 `/visual-solution:visual-solution-immersive-director` 啟動（用安裝程式裝的是 `/visual-solution-immersive-director`），或直接這樣說：

```text
使用 visual-solution-immersive-director 盤點這個網站案件，先判斷製作模式與目前階段，再推進到下一個可驗收成果。
```

Codex 用 `$visual-solution-immersive-director` 指定 Skill，句子相同。

補上案件資訊，第一輪會更準確：

```text
使用 visual-solution-immersive-director 開始這個案件。
- 客戶資料、CIS 與素材都在這個資料夾
- 首頁區塊順序已和客戶確認：Banner → 企業簡介 → 產品 → 案例 → CTA
- 參考 https://example.com：只取 Banner 的照片錯位疊層，其他原創
- 產品外型與包裝不能改
```

### Skill 每一輪會做什麼

1. 先依第 2 節核對套件更新與安裝同步、重讀規則，再讀既有檔案、進度、已確認的決策與工程限制。已有方向或確認就沿用，不重新提案、不重問；無法確認新版時會明說。
2. 判斷案件分級與製作模式，找出目前該做的階段。
3. 只讀這個階段需要的規則文件。
4. 做出看得到的東西：提案是可觀看的畫面，試做是可操作的瀏覽器預覽，不是只交文件。
5. 把決策回填正本與進度檔。已授權的範圍連續做完，遇到確認點才停下來問你。

每次開始、接續或進入新階段，Skill 會先說明目前階段與建議模型（見第 11 節）。第一次開始執行時，也會先問你這個案子要不要授權 Codex 執行已定規格，以及產圖是否採預設做法（Claude 操作 ChatGPT 網頁生成、你下載成品），答案記在進度檔，之後不重問；沒授權 Codex 就全部由 Claude 做。

### 接續既有案件

說「繼續這個案件」即可。Skill 會讀案件根目錄的 `README.md` 與 `experience-status.md`（進度唯一正本），從上次停下的地方往下做。

換電腦、換模型或隔很久再做之前，先請它「更新進度檔」，確認已確認項目、素材與預覽路徑、已知問題和下一步都已寫入。換電腦時，先等雲端硬碟同步完成再說「繼續這個案件」，不然 Skill 讀到的是舊檔。

## 5｜流程與五個確認點

| 順序 | 階段 | 你的確認 |
|---|---|---|
| 1 | 內容盤點與模式判斷 | 核對事實與不能改的資產 |
| 2 | 2–3 個原創方向 | ① 方向 |
| 3 | 視覺提案 | ② 視覺 |
| 4 | 動態提案與分鏡 | ③ 動態 |
| 5 | 素材、規格與核心片段試做 | ④ 核心片段 |
| 6 | 完整 2560×1280 桌機首頁 | ⑤ 完整首頁 |
| 7 | 內頁 | 你提出後才開始，代表頁先確認 |
| 8 | RWD | 你另外授權才開始 |

忠實重建的案子跳過 ①；② 改為來源構圖與品牌替換的對照，③ 改為實測來源動態後的還原分鏡。

開案時 Skill 會先問你是否授權 Codex 執行已定規格，以及產圖方式，答案記在進度檔。核心片段確認後，若已授權且場景表、規格與素材齊全，完整首頁與內頁的實作可交給 Codex，Claude 做最後實看。產圖預設由 Claude 操作 ChatGPT 網頁生成、你下載成品，不用 Codex 產圖。這是建議分工，不是強制。

### 盤點與模式判斷

- **Skill 交付**：內容盤點（客戶事實、策略推論、缺口分開列）、不能改的正式資產清單、CIS 完整度、案件分級與製作模式。
- **你要看**：事實有沒有錯、不能改的資產有沒有漏、缺的資料能不能補。

### ① 方向

- **Skill 交付**：2–3 個概念真正不同的方向，各有核心概念、Hero、只屬於這個品牌的 Signature Moment、技術輪廓與風險；附 100 分加權評分、推薦理由與取捨。
- **你要看**：概念是不是從品牌發展出來，而不是套用常見效果；推薦方案犧牲了什麼，能不能接受。
- **可以這樣回**：「選方向二」「方向一，但 Hero 改用方向三的做法」「你依推薦代選，記錄下來」。

### ② 視覺提案

- **Skill 交付**：可在瀏覽器觀看的提案頁，包含用色比例、字體實際樣張、ICON、背景圖形、人物或產品表現、功能圖解、UI 樣式、素材狀態，以及 2560×1280 的 Hero、代表內容段與 CTA 關鍵構圖和全頁概要。
- **你要看**：第一焦點、次要訊息與行動入口是否清楚；正式品牌素材是否用對；後半頁是否也有規劃，而不是只有首屏。缺 CIS 時，AI 建議的配色與字體經你確認後成為「本案網站視覺約定」，不等於客戶的正式 CIS。
- **可以這樣回**：「視覺確認，紅色面積再少一點」「字體確認，ICON 改成線性」。
- **注意**：視覺確認不包含動態。

### ③ 動態提案

- **Skill 交付**：Hero → 首次轉變 → 代表場景的分鏡，每段都有起始、過程、結束畫面，說明圖層、觸發、節奏、轉場與回捲、文字何時可讀、減少動態的做法與技術風險；另附全頁的動態強弱規劃（重點轉場、輕量銜接、安靜閱讀）。
- **你要看**：每個動態的目的是引導視線、解釋內容還是延續前後關係；文字和 CTA 會不會被動畫拖延；往回捲時怎麼還原。
- **可以這樣回**：「分鏡確認，開始做核心片段」「第二段轉場太強，改成輕量銜接」。

### ④ 核心片段

- **Skill 交付**：可操作的瀏覽器預覽，包含 Hero → 首次轉變 → 代表場景，以及一段真實內容的閱讀段；已在 2560×1280 自查，附預覽方式。
- **你要看**：自己在 2560×1280 操作，往下捲、往回捲、快速捲，實際 hover 與點擊。閱讀段停留時間夠不夠，有沒有卡頓、露底或空白帶。截圖和錄影不能代替實際操作。
- **可以這樣回**：「片段確認，展開完整首頁」，或具體回饋（見第 6 節）。

### ⑤ 完整桌機首頁

- **Skill 交付**：整頁場景表，以及完整的 2560×1280 首頁：全部內容、素材、動態節奏、下滑後固定的 Nav、Footer、右下角回到頂部與 CTA，自查到 Footer。
- **你要看**：從頂端走到頁尾，後半頁有沒有掉級；圖片有沒有裁錯或露底；CTA 是否清楚且連得到；已確認的區塊順序有沒有被改動。
- **可以這樣回**：「首頁確認」。

> 在一般螢幕看 2560×1280：用 Chrome 開啟預覽頁 → 開發者工具 → 切換裝置工具列（⌘⇧M／Ctrl+Shift+M）→ 尺寸選 Responsive（回應式）並填入 2560 × 1280 → 縮放選 Fit to window（符合視窗）。

## 6｜確認與回饋

### 你說「好」時確認了什麼

- 五個確認點分開算，各自記錄版本與範圍。
- 只涵蓋當下展示的內容。還沒展示過的，不算已確認。
- 確認點之間不會一直問你：素材處理、細節、程式修正與重新檢查，會在已授權範圍內連續做完。
- 你拍板的修改會先寫回正本再實作。像「人物不要拆」這類回饋會變成素材約定，不會只留在對話裡。
- 「AI 自查通過」「AI 自評」「你確認」是三件不同的事，分開記錄；分數不代表完成。

### 回饋怎麼給

講清楚「哪裡、看到什麼、想要什麼」，能附參考或數值更好。以下整理自實測案例：

| 狀況 | 有效的說法 |
|---|---|
| 品牌個性抓不到，例如不夠可愛 | 直接給字體與參考網站當基準；品牌個性很難讓 AI 自己判斷 |
| 區塊之間太平、沒有重點 | 提供 CIS 輔助圖形的應用頁當參考，要求區塊之間加上銜接 |
| 編排重複，例如好幾段都是左文右圖 | 指出哪幾段重複，要求每段有自己的構圖邏輯 |
| 參考站的風格被整套搬過來 | 說清楚只取哪一部分，例如「只取版面節奏，不取字體」 |
| 動態幅度看不出來 | 在 2560 寬實看後給數值，例如位移從 28px 加大到 72px |
| 捲動換層太黏或太快 | 實際捲過後指出位置與感受，例如「A 到 B 要捲太久才換」 |

覺得不對但說不出原因時，可以請它「先自查，列出目前最弱的三處並修正」，再從結果討論。

### 可以授權的事

- 代選：「方向你依推薦選，記錄下來」。
- 連續執行：「這輪細修不用問我，做完再給我看」。
- 跳過確認點：明確說要跳過哪一個，Skill 會照做並記錄。

效果做不出來時，Skill 不會包裝成「完成，之後可優化」。同一個原因修兩輪沒改善就換做法；需要改動已確認的方向或缺少關鍵素材時，會帶著具體方案來問你。

## 8｜用 Eagle 整理案例

`eagle-visual-solution-curator` 會把你喜歡的網站、截圖或影片整理成日後找得回、看得懂的 Eagle 紀錄。只做分析時不必連線 Eagle；要讀取現有分類或寫入時，Eagle 需要開啟並啟用 MCP 外掛。

```text
整體視覺方案：這個網站的 Banner 我喜歡文字沿著產品輪廓留白、照片錯位疊層，幫我整理成 Eagle 紀錄。https://example.com
```

- 開頭註明「整體視覺方案」。沒註明時會先問你屬於哪個方案，其他方案有各自的 Skill。
- 說清楚喜歡哪裡，以及收藏範圍是整站、區塊還是某個互動。你的原話會保留為「收藏理由」，AI 的觀察另外列出。
- 產出的是「待審核」紀錄：名稱、備註（收藏理由、核心參考價值、視覺與影像、互動、轉用條件、證據範圍）、資料夾與標籤。資料夾和標籤只用 Eagle 裡已經存在的，缺的會另列「建議擴充」，不會自行新增。
- 你核准後才寫入 Eagle，寫完會回讀核對，回報成功與失敗數量。
- 案例備註是參考，不是客戶已確認的設計指令，也不代表素材可以商用。

## 10｜Git 推與拉

網站做完要備份到公司 Git（`http://192.168.168.134/client-html-demo`），也能在另一台電腦拉下來繼續。你只要開口，Skill 照公司流程跑指令；只有帳密那一步要你自己輸入。伺服器在公司內網，家裡要先連 VPN。

推的是完整網站資料夾（首頁、內頁、css、js、assets 同一層）。案件資料夾（素材、文件、進度檔）在雲端硬碟，不進 Git。

### 一次性準備

| 步驟 | 誰做 | 說明 |
|---|---|---|
| 1. 裝 Git | 你 | Mac 在終端機輸入 `xcode-select --install`；Windows 到官網下載，一路預設。要管理者密碼找安志或阿久 |
| 2. 設身分 | Skill 問、Skill 設 | 名字格式「暱稱(全名)」例如 `LIN(林盈岑)`，信箱是公司信箱。Skill 第一次推送前會檢查，缺的問你 |
| 3. 拿帳密 | 你 | 帳號是公司信箱 @ 前面的英文；密碼向工程師申請，開好後私訊給你 |
| 4. 第一次輸入帳密 | 你 | 第一次推送會要帳密，在自己的終端機輸入一次，系統就記住；Skill 不會幫你輸入 |

### 情況 A：新網頁第一次推上去

1. 對 Skill 說：「推到公司 git，專案 ID 用 `abc-web`，客戶名稱『某某公司』」。專案 ID 用英文、數字、連字號。
2. Skill 會：檢查 Git 與身分 → 在網站資料夾建立儲存庫、加 `.gitignore`、提交 → 加遠端 → 推送（主機自動建立專案）→ 回報專案網址並記進進度檔。
3. 第一次推送若跳出帳密，Skill 會停下來請你在自己的終端機執行：

   ```bash
   git push -u origin main
   ```

   輸入帳號密碼一次，成功後跟 Skill 說「推好了，繼續」。

### 情況 B：在另一台電腦拉下來

1. 對 Skill 說：「把 `abc-web` clone 到這裡」，或自己執行：

   ```bash
   git clone http://192.168.168.134/client-html-demo/abc-web.git
   ```

2. 帳密自己輸入。拉下來的是網站資料夾；案件資料夾請從雲端硬碟開。
3. 說「繼續這個案件」，Skill 會先讀 README 與進度檔再接續。

### 情況 C：改完要同步上傳

1. 對 Skill 說：「同步到 git」，想的話加一句修改說明。
2. Skill 會：看變更 → 加入檔案 → 提交（修改說明）→ 先拉同事的最新版 → 推送 → 回報推了幾個檔案。
3. 沒衝突就結束。有衝突時 Skill 會逐檔列出「自己的版本」和「同事的版本」，你回「保留我的」「保留同事的」或「兩個都留」，它改好檔案、提交「解決衝突」、再推。你也可以說「我自己在 VSCode 處理」，處理完再叫它推。

### 注意

- 做完一個階段再推，不用每改一行就推；推之前 Skill 會先列出要送的檔案給你看。
- Skill 不用 `--force`、不刪遠端專案；要動別人的東西會停下來問。
- 案件資料夾在雲端硬碟裡有 `.git` 時，推送前後別在另一台電腦同時操作。
- 不想用 Skill 時，照公司文件用 VSCode 的「原始碼控制」按鈕做也可以：[內部 Git 專案空間使用說明](http://posthub.miracle-single.tw/docsys/#/articles/publish/2335)。

## 11｜模型建議

Skill 會在每個新階段說明建議模型與原因，最後由你決定；這是工作分工建議，不是能力評測或強制門檻。若平台提供 Astra 與 Sol，Astra 代表高推理與創意整合，Sol 代表主力執行，實際名稱以你的模型選單為準。

| 建議 | 適用階段 |
|---|---|
| Astra | 模式判斷與原創方向、視覺提案、動態分鏡、素材方向、核心片段首次試做、完整首頁首次延伸、視覺與動態總評 |
| Sol | 資料盤點、依已定規格整理素材、已確認版型的內頁、文案套用、局部微調、一般 bug 修正、功能與內容 QA、RWD、交付整理 |

遇到品牌定位衝突、跨場景的問題或修正反覆失敗時，Skill 會建議改用 Astra。切換模型前，先請它更新進度檔。

## 12｜常見問題

**沒有 CIS 可以開始嗎？**
可以。Skill 會盤點 Logo、產品、官網與照片裡的品牌線索，針對缺的部分提出具體建議與樣張，經你確認後作為本案網站視覺約定。

**為什麼只做 2560×1280？**
這是本流程第一階段的驗收尺寸，構圖、裁切、字級、捲動距離與效能都在這個尺寸實看。RWD 要另外提出，桌機完成不代表 RWD 完成。本案需要其他桌機尺寸時可以直接指定。

**可以不做片段，直接要完整首頁嗎？**
可以明確要求。Skill 會先完成全頁構圖、素材與動態強弱的規劃再實作，不會只做 Banner。

**可以沿用高效方案的母版或案例嗎？**
不能直接沿用。高效方案的母版策略、產圖管道、案例結論與額度換算都不適用，歷史案例只供查閱。

**會自動叫 Codex 或開多個 AI 代理嗎？**
不會自動叫。每個案件開始時 Skill 會先問你要不要授權 Codex 執行已定規格，以及產圖方式，答案記在進度檔，之後不重問；沒授權就全部由 Claude 做。建議的分工是：Claude 負責到核心片段確認的設計工作與之後每一輪的實看；核心片段確認後，場景表、規格與素材齊全時，可交給 Codex 執行完整首頁與內頁，Claude 只做最後實看。產圖不走 Codex：由 Claude 操作 ChatGPT 網頁生成、你下載成品。

**製作時一直跳出權限詢問，可以減少嗎？**
Claude Code 可以選用 `python3 install.py --case 案件資料夾路徑`，在該案件建立 `.claude/settings.json`，讓檔案修改與終端機指令不再逐項詢問；強制推送、`git reset --hard`，以及對根目錄或家目錄執行的 `rm -rf` 仍會擋下。案件已有設定檔時不會覆蓋。這是選用功能，不影響流程中的確認點。

**換電腦或換模型要注意什麼？**
先請 Skill 更新 `experience-status.md`：目前階段、已確認與未確認項目、不可改的內容、素材與預覽路徑、動態規格、已知問題和下一步。接手時說「繼續這個案件」，就會從這裡接續。換電腦時等雲端硬碟同步完成再開始。

## 13｜疑難排解

| 狀況 | 原因 | 處理 |
|---|---|---|
| `/plugin marketplace add` 失敗 | GitHub 帳號還沒被加為協作者，或這台電腦的 git 還不能存取私人 repo | 確認已接受協作者邀請；照第 2 節「安裝前：先讓電腦登入 GitHub」請 Claude Code 幫你登入，再重試 |
| Plugin 裝好後技能清單出現兩份 | 以前用安裝程式裝過，舊的還在 `~/.claude/skills` | 到當初的 `skill/` 資料夾執行 `python3 install.py --uninstall`，再重新開啟 Claude Code |
| Plugin 沒拿到新版 | 自建來源預設不自動更新 | `/plugin` → Marketplaces 開啟 Enable auto-update，或輸入 `/plugin marketplace update visual-solution-workflow` |
| 安裝後技能清單找不到 | AI 工具還沒重新載入 | 重新開啟 Claude Code 或 Codex；執行 `python3 install.py --status` 確認 |
| `--status` 顯示 `[未安裝]` | 尚未安裝或已被移除 | 重新執行安裝 |
| `--status` 顯示 `[斷掉]` | 捷徑指向的資料夾被搬走或刪除 | 把 clone 的資料夾放回原位，或在新位置重新執行 `python3 install.py` |
| 安裝出現 `[跳過]`，結果是「未完成」 | 安裝位置已有同名、但不是這支安裝程式裝的資料夾，例如另外裝過的 `gsap-*` | 核對該資料夾的來源；確定可以替換後自行移走，再重新安裝 |
| `--status` 顯示 `[歷史殘留]` | 舊版五角色 Skill 還留在電腦上 | 不影響使用；要清理時先核對來源再手動處理 |
| 安裝出現 `[提醒]`，說 name 不一致 | SKILL.md 的名稱與資料夾名稱不同，可能無法載入 | 回報維護者 |
| `--update` 失敗 | 沒有網路或權限，或本機有修改與遠端分歧 | 先確認網路；本機修改或分歧請找維護者；臨時可向維護者拿 zip，用 `python3 install.py --copy` 重裝 |
| 已經裝過高效方案的 `eagle` | 若原本是高效套件建立的捷徑，安裝本套件後 `eagle` 會改由本套件管理（目前兩份內容相同）；之後執行 `--uninstall` 時 `eagle` 也會被移除 | 移除本套件後，重新執行高效套件的安裝程式，恢復 `eagle` |
| Eagle 連不上 | Eagle 沒開，或 MCP 外掛未啟用 | 開啟 Eagle 並啟用外掛。未連線時仍可做分析，分類會標「待取得即時分類」 |


## 14｜靜態切版到 EVO：設計師實際怎麼用

```text

工程師套件：填 evomni-page-composer 的本機位置

請先讀現有工程與進度，查工程師的範本資料再切版。
共用與單頁 CSS／JS 分開，每頁只引用自己需要的資源。
請主動判斷客戶可編輯項目；不確定用途或會影響設計時再問我。
完成完整可預覽的網站，交付時整理頁面對照表。
```

先用本教學前面的指令叫用對應 Skill，再貼這段即可。續作只需補上本輪範圍，已確認的資料不用重填。

### 哪些事交給 AI 判斷

| 遇到的需求 | AI 要做什麼 | 你需要做什麼 |
|---|---|---|
| 選單、FAQ、麵包屑等平台元件 | 查範本規格，保留必要結構，再配合本案外觀 | 確認設計與操作 |
| 自製品牌區塊 | 使用 designer-tpl-* 命名，完整做出設計與效果 | 確認構圖與效果 |
| 消息、產品、證書、團隊、輪播圖片 | 判斷內容來源與逐筆編輯需求，查平台契約 | 用途不明時回答是否需自行增刪 |
| 平台資料或文件不足 | 記錄具體缺口交工程師確認，先完成可做的靜態部分 | 提供已知資料即可，不必判斷 data 屬性 |

自製範例是 `designer-tpl-about`；平台 FAQ 仍保留 `tpl-faq001` 等原名。既有案件不會自動整站改名。你不用先背範本清單，AI 會讀工程師套件；查到規格不等於已完成 EVO 轉檔。

### CSS 在切版時就分好

以下是新案示意，既有案件沿用自己的位置與編譯工具。CSS 由 SCSS 編譯產生，不手動維護兩份相同樣式。

```text
網站/
├─ index.html
├─ about.html
├─ contact.html
├─ scss/
│  ├─ _common.scss             全站變數、字體、容器、按鈕
│  ├─ _header.scss             共用頁首
│  ├─ _footer.scss             共用頁尾
│  ├─ _innerpage-default.scss  內頁共用 Hero、CTA
│  ├─ evomni-root.scss         只匯入共用樣式
│  ├─ index.scss               首頁專用
│  ├─ about.scss               關於我們專用
│  └─ contact.scss             聯絡我們專用
├─ css/                       編譯輸出
│  ├─ evomni-root.css
│  ├─ index.css
│  ├─ about.css
│  └─ contact.css
└─ js/
   ├─ header.js                選單、漢堡、語系
   ├─ footer.js                頁尾、回頂部、全站初始化
   ├─ index.js                 首頁專屬互動
   └─ about.js                 關於我們專屬互動
```

例如 `about.html` 的樣式引用：

```html
<link rel="stylesheet" href="css/evomni-root.css">
<link rel="stylesheet" href="css/about.css">
```

若用到 Swiper 等套件，另載入必要套件 CSS，順序依本案確認。關於我們不能靠載入 contact.css 才正常。兩頁共用的 Hero 放共用檔，只有關於我們使用的沿革放 about.scss；合理的單頁差異可以覆寫，但 AI 要檢查實際權重。

工程師轉 EVO 時再將同一份來源對應到正式站的全站／單頁資源。既有站可能有不同輸出方式，例如 evo266200 正式 root 還需保留 index；不能照新案示意直接刪掉舊站的引用。

### JS 依功能分工

`header.js` 管選單、漢堡、語系；`footer.js` 管頁尾、回頂部與全站初始化。需要全站 Lenis 時，在 footer.js 建立一次；AOS 全站初始化也集中處理。Lenis 依設計需要啟用，不是每站必加。

首頁動畫放 index.js，關於我們動畫放 about.js。每頁只引用共用、本頁及必要套件；沒有專屬互動就不用建立空 JS。AI 負責等待套件、DOM 與共用 HTML 就緒，並避免重複啟動；放在頁尾不代表非同步內容已經載完。

靜態預覽需有實際可用的套件與初始化。轉 EVO 後，data-vendor 是載入宣告，不會自動啟動輪播；套件版本與正式接入方式交工程師依目標站台確認。畫布預覽設定與前台初始化也分開核對。

### 內頁 HTML 與客戶可編輯內容

AI 會將內頁識別放在 main 內第一層，避免轉檔後遺失：

```html
<main id="main-content" class="main-content">
  <div class="inner-page about-page">
    <section class="designer-tpl-about">
      <h1 class="main-title">關於我們</h1>
      <p class="description">本案已確認的公司介紹。</p>
    </section>
  </div>
</main>
```

這只是主要內容示例；交付的靜態網站仍包含完整 head、頁首、頁尾和資源。樣式可寫 `.about-page .main-title`，不能寫 `.about-page .main-content`，因為 main-content 在外層。

客戶會更新的文字、圖片與清單保留在可編輯內容中。AI 主動判斷增刪、排序、換圖需求；資料庫產品、平台 FAQ 與一般圖片清單各用適合的契約，不一律套同一種標記。第一筆作樣板時，各筆結構一致。

例如「100 年經驗」改成「120 年經驗」，動畫應跟著跑到 120。AI 要測試改字、換圖及項目數改變後的效果；暫時的拆字標籤、數字動畫與輪播複製節點不能存回原始內容。後台存檔的接入由工程師驗證，動畫失敗時內容仍須看得到。

### 首次製作要包含什麼

首次就一起完成共用 Header／Footer、回頂部、Cookie 提示與有內容的隱私權政策頁。「隱私權政策」文字須連到本案實際頁面；缺正式政策文案時完成草稿並列待確認項目，不把草稿當客戶已核准。

Cookie 外觀與文字、選單、FAQ、麵包屑、跑馬燈依 Skill 的指定參考。輪播用 Swiper，區塊淡入淡出用 AOS，複雜動態依已確認設計使用 GSAP；固定圖片效果優先處理於素材。Footer 版權列沿用規範的 Designed by 米洛科技有限公司，不加客戶 © 或年份。

### 校稿完成後怎麼交工程師

你可以直接說：

```text
請整理這版的工程師交付資料。
依實際檔案列出每頁 HTML、SCSS／CSS、JS、共用依賴、
套件版本、動畫功能與客戶可編輯項目。
檢查資源缺檔、路徑、單頁獨立預覽及本輪範圍內的 RWD。
保留完整靜態預覽，列出仍需工程師接入或確認的地方。
```

AI 會填好這類對照表，你不用手填。下面只是示例，不代表本案已經完成：

| 頁面 | HTML | 專屬 SCSS → CSS | 專屬 JS | 共用依賴 | 套件 | 互動效果 | 客戶可編輯 |
|---|---|---|---|---|---|---|---|
| 關於我們 | about.html | about.scss → about.css | about.js | root CSS、header/footer HTML 與 JS | Swiper／實際版本 | 數字滾動、證書輪播；附初始化函式 | 數字、證書圖片與順序 |
| 聯絡我們 | contact.html | contact.scss → contact.css | 無（本例無專屬互動） | 同上 | 無額外套件 | 電話／Email 連結 | 聯絡資訊 |

表下附啟動與編譯方式、套件與程式順序、初始化時機、檢查結果及待確認項目。表單沒有後端時明示待串接，不以假的成功訊息當完成。

### 四種進度分開看

| 狀態 | 代表什麼 |
|---|---|
| 靜態預覽驗證 | 已在瀏覽器測過指定頁面、動畫及授權尺寸 |
| 客戶確認 | 客戶確認了特定版本與範圍 |
| 工程師轉檔 | 工程師已處理 EVO 輸出與後台接入 |
| 後台／前台整合驗證 | 已實測編輯、儲存、發布後內容與效果 |

目前這輪完成的是 Skill 與教學文件整理，尚無本輪新規則的實際案件轉檔驗證。未來交付時仍需依每案實際結果填寫。

### 遇到問題可以這樣說

- 「關於我們拿掉其他頁 CSS 就跑版，請找出藏錯位置的共用樣式。」
- 「客戶改數字後，動畫還是舊值，請讓動畫讀取最新內容。」
- 「輪播圖片要讓客戶自行增刪，請查工程師套件的編輯契約。」
- 「只修這個區塊，保留其他頁與已確認動態。」
- 「套件規格與工程師指南不同，請列出差異及待確認項目。」
