第一次使用｜從沒有安裝任何工具開始

  1. 01準備帳號

    確認公司指定工具、登入與 repo 權限。

  2. 02安裝 Skill

    讓 AI 依來源文件設定適用規範。

  3. 03驗證可用

    重新開啟，確認規範與檔案都能讀到。

這一節假設你還沒安裝 AI 工具，也沒有任何 Skill。先完成下面三個階段，再開始案件；此時不需要先會寫程式，也不用先準備整套工程環境。

A｜準備帳號與使用權限

先向 LIN／維護者確認公司指定的工具、帳號與可使用權限：

  • Claude 帳號：需要能使用 Claude Code，之後才可操作本機檔案與製作網站。
  • ChatGPT 帳號：本案使用 Codex 或 ChatGPT 產圖時準備。
  • GitHub 帳號：把帳號名稱提供給 LIN，請他加入公司私人 Skill repo 的協作者，並接受邀請。

還沒有帳號或不確定公司用哪個方案，先請維護者協助，不必自行購買。登入與帳號授權由你本人操作。

B｜安裝 Skill 與必要工具

Skill 是 AI 的工作規則，和 AI 軟體分開安裝。所需入口如下：

  • 整體視覺主 Skill：從品牌資料開始提案及製作整體視覺網站。
  • LIN／lin-frontend：共用切版與校稿規範。

AI 工具已能使用後，才把下面這段貼進目前使用的本機工作。Git（取得及管理檔案的工具）與 Python（執行安裝程式的工具）由 AI 先檢查，缺少時協助準備；需要電腦管理者密碼或公司權限時找維護者處理。

貼給已安裝的 AI：

這台電腦是第一次設定，尚未安裝網站製作的 Skill。
目前使用工具：（填 Claude Code／Codex）。
請先檢查本機 Git、Python 與 GitHub 存取權限，協助準備必要工具。
整體視覺來源：https://github.com/world-yingcen/Visual-Solution-Workflow
LIN 來源：https://github.com/world-yingcen/lin-skill
請先讀這兩份來源的安裝文件，安裝本工具需要的整體視覺主 Skill 與完整 lin-frontend。
來源庫放在固定本機位置，不放雲端同步資料夾；只安裝到目前工具對應的 Skills 位置。
Claude Code 的整體視覺優先使用 Plugin；依文件採另一種方式時，同一工具不要重複安裝兩份。
若尚無私人 repo 權限，請列出需要 LIN 協助的項目。
需要登入或授權時讓我本人操作，不在對話中索取密碼。
目前只設定工具與 Skill，不開始製作網站、不推送或部署。

Claude Code 與 Codex 都要使用的人，各自在對應工具完成一次安裝；在其中一個工具裝好，不代表另一個也能讀到。維護者的詳細操作見 安裝文件。

C｜重新開啟並驗證，再開始案件

安裝完成後重新開啟目前使用的 AI 工具，開啟目前的本機工作，再貼下面這段：

請確認本工具可使用 visual-solution-immersive-director 與 lin-frontend，並重新讀取規範。
請回報實際安裝位置、使用版本與缺少的項目，確認能讀取目前本機資料夾。
先不要開始製作網站。安裝或更新未完成的部分請如實標示，整理可執行的處理方式。

做到這裡再往下： AI 已讀到本案所需的 Skill，也能讀取本機資料夾。若失敗，把錯誤畫面與回覆交給維護者；完成後再開啟真正的案件資料夾，進入第 1 步。

需要 ChatGPT 產圖時，再設定 Chrome

依本案選定的產圖方式準備。採用「Claude 操作 ChatGPT 網頁、你下載成品」時：先從 Chrome 官方下載頁安裝瀏覽器，再依 Claude in Chrome 官方設定說明安裝與連接擴充功能，並由你本人在 Chrome 登入 ChatGPT。連接後請 Claude 確認能讀取指定分頁；此時只驗證連線，不產圖。

若本案使用其他影像工具，依指定方式設定並記入進度，不必為此額外啟用 Chrome 產圖管道。Eagle 與網站編譯工具則在需要的製作階段再核對，不要求第一次就全部安裝。

第 1 步｜準備並開啟案件資料夾

  1. 01放到自己的 Google Drive

    複製專案提供的檔案，不在共用區執行。

  2. 02確認 PDF 讀取方式

    先詢問要現在先讀，還是用到再讀。

  3. 03請 Skill 整理資料夾

    盤點、分類，說明工作入口與資料缺口。

每輪開始工作前，AI 會先檢查 Skill 來源與案件工作資料夾是否由 Git 管理；有 Git 就先安全更新，再讀規範與進度。連結安裝不必重新複製。若有未提交修改、版本分歧或無法連線，會保留檔案、說明未完成更新，再繼續不受影響的工作。

A｜將專案檔案放到自己的 Google Drive

請將專案提供給你的檔案，複製到自己的 Google Drive 案件資料夾，請勿直接在共用區執行。

使用電腦上可存取的 Google Drive 同步資料夾，等檔案同步完成後，再用 AI 工具開啟這份案件資料夾。

B｜確認 PDF 讀取方式

PDF 可以保留。Skill 會先列出案件資料夾及子資料夾中的 PDF 並檢查大小，未超過 10 MB 才在讀取內容前詢問：「這些 PDF 需要讓 AI 現在先讀嗎？還是有要用到再讀？」

單一 PDF 超過 10 MB（10,000,000 bytes），AI 一律拒絕讀取，即使你要求也不例外。請直接截圖提供需要的重點，或將重點整理成 Markdown（.md）檔案提供；原檔保留並標記未讀取。

為避免不必要的 token 消耗，選擇用到再讀的 PDF 會先集中到 04_型錄與原始素材/PDF_待用時讀取/，並標記尚未讀取；後續需要時只讀相關檔案或頁面。

C｜請 Skill 整理資料夾

檔案已放到自己的 Google Drive 後，請本案適用的 Skill 盤點並整理資料夾。你不需要先自行重新命名或分類。

貼給 AI：

使用本案適用的 Skill，幫我整理案件資料夾。
案件位置：（填自己的 Google Drive 在本機的案件資料夾完整路徑）。
我已將專案提供的檔案放好；請勿操作共用區的原始檔案。
遇到 PDF 請先檢查大小，單一檔案超過 10 MB 一律拒絕讀取；未超過上限才詢問要現在先讀，還是有要用到再讀；選擇用到再讀的 PDF 請整理到獨立資料夾並標記尚未讀取。
請先讀取資料與既有進度，再依本案規範整理資料夾、素材、文件及目前工作入口。
保留既有網站的資源引用與已確認成果，列出整理結果及缺少的資料。
本輪先整理資料，不開始設計或切版。

整理後的資料夾會像這樣

需求、品牌素材、頁面資料與待確認事項分開放；先看 README.md，就能找到目前的工作入口。

做到這裡再往下： 檔案位於自己的 Google Drive 案件資料夾，PDF 的讀取方式與暫存位置已確認，Skill 已完成整理並說明資料位置與缺口。

當作品質標準

原創
參考它的完成度，方向依品牌由你提案

參考只是證據，方向從本案品牌與內容發展，不套用參考網站的風格。

預設建議由 Claude 主導設計與每輪驗收；核心片段確認、整頁規格與素材齊全後，可由已授權的 Codex 執行完整首頁、內頁與細修。這是建議分工；若你只使用一個工具，直接告訴 AI，由目前可用工具推進並說明能力缺口。

同案授權記入進度，之後沿用。需要切換工具時，先請目前的 AI 記錄確認內容與下一步，再讓接手工具讀取，不必自己搬運整段對話。

參考用途請選清楚：忠實重建是沿用約定的版面及動態；指定特徵轉譯是保留喜歡的特徵、重新設計；原創方向是以本案品牌發想，參考只校準品質。

做到這裡再往下： AI 說明本案流程、工具分工與缺少資料。

素材與產圖｜需要時在這裡配合

AI 應先盤點客供素材，再提出缺少圖片的用途與構圖。正式 Logo、產品、角色及 IP 使用客供原檔，不用生成近似版。

預設產圖由 Claude 透過 Claude in Chrome 操作你已登入 ChatGPT 的 Chrome 網頁；你再下載成品到指定位置。先請維護者確認擴充功能與登入狀態。若無此工具或本案指定其他產圖方式，讓 AI 記錄替代方式及需要你配合的步驟。

每張圖先確認用途、主體位置、文字留白、比例與檔名。下載時照指定檔名存到案件素材資料夾，再告訴 AI 已放好；AI 實看後才裁切、壓縮與置入。不要只貼預覽縮圖當正式成品。

貼給 AI：

請先列出本輪需要的圖片，以及可以沿用的客供素材。
缺圖請給我可以看的構圖建議，說明用途、比例、文字留白、檔名與存放位置。
依本案已記錄的產圖方式執行，需要我下載時逐張告訴我。
成品放好後請實看，檢查是否適合版面，再處理與置入。

做到這裡再往下： 圖片用途與風格符合方向；正式素材、生成素材與暫代圖已區分，檔案能在案件資料夾找到。

第 3 步｜確認設計方向

從方向到完整版本的確認流程

  1. 01人工開案

    提供案件資料夾、客戶資料、CIS 與素材。

  2. 02Skill盤點與模式判斷

    分開事實、推論與缺口，決定原創、特徵轉譯或忠實重建。

  3. 03Skill提 2–3 個方向

    概念真正不同，附評分與推薦。

  4. 04人工① 方向確認

    選定一個，或授權 AI 依推薦代選。

  5. 05Skill視覺提案

    用色比例、字體、ICON、人物與 2560×1280 關鍵構圖。

  6. 06人工② 視覺確認

    確認視覺，不等於確認動態。

  7. 07Skill動態提案與分鏡

    起始、過程、結束，轉場與回捲。

  8. 08人工③ 動態確認

    先看分鏡，確認後才進實作。

  9. 09Skill核心片段試做

    素材、規格與可操作預覽，在 2560×1280 自查。

  10. 10人工④ 核心片段確認

    實際捲動與操作，不是看截圖。

  11. 11Skill完整桌機首頁

    全頁內容、動態節奏、Nav、Footer 與 CTA，自查到頁尾。

  12. 12人工⑤ 完整首頁確認

    整頁一次確認。

  13. 13人工提出內頁

    代表頁先確認，再展開同類頁。

  14. 14人工完成 RWD 再校稿

    桌機內部確認後接續 RWD，完整檢查再交客戶。

原創案件由 AI 提出 2–3 個概念不同的方向，說明適合的原因與推薦。看它是否符合品牌、客群與網站目的；忠實重建則先確認保留與可替換範圍，沿用約定參考。

貼給 AI：

我選擇方向：（填名稱）。
想保留：（填喜歡的部分）。
需要調整：（填不適合的部分）。
請記錄確認方向，再準備視覺提案。

做到這裡再往下： 方向與參考使用邊界已清楚。沒有 CIS 時，AI 提出的色彩、字型等建議需經你確認，才能作為本案網站的視覺約定。

第 4 步｜確認視覺提案

看實際構圖、色彩比例、字體、圖示、背景圖騰、形象圖片與功能圖解，以及它們怎麼用在主要區塊。AI 應提供可觀看的畫面，不能只有風格形容詞或色碼清單。

確認基準是 2560×1280 的瀏覽器內容區域。你的螢幕較小時，請 AI 提供該尺寸截圖或對應預覽，自己再看可操作版本；縮小截圖不代表已驗證小螢幕版。

請包含往回捲的行為、文字閱讀時間、按鈕操作，以及減少動態時的呈現。
讓我先確認做法，再開始核心片段試做。

做到這裡再往下： 你理解並同意動態做法，再回覆「這版動態提案確認，請試做核心片段」。此時尚未確認實際動畫成品。

第 6 步｜試玩核心片段

AI 做出最能驗證構圖與動態的片段，提供可操作預覽。自己試正反向捲動、快速捲動、點擊與重新載入，確認速度、閱讀與操作符合預期。

貼給 AI：

請完成核心片段並在 2560×1280 自行檢查。
開啟可操作預覽，告訴我要怎麼試、這次包含哪些區塊，以及尚未完成的部分。

做到這裡再往下： 片段符合預期，再回覆「這版核心片段確認，請記錄規格並延伸完整桌機首頁」。片段通過只代表該範圍通過。

第 7 步｜確認完整桌機首頁

從頁首看到頁尾，檢查內容層級、圖片裁切、留白、全頁動態與 CTA（引導使用者採取行動的按鈕）。試選單、連結、輪播、下滑固定導覽與右下角回到頂部。

使用 Codex 分工時，由 AI 先整理全頁場景、規格及素材位置，再交接；完成後仍須實看驗收。AI 自查有缺陷應先修正，暫代文案、缺圖與未完成功能要明列。

切版完成後，AI 會提醒你檢核專案檔案大小，並列出網站使用的非 WebP／SVG 圖片及其路徑、大小。請自行轉成適合網頁的格式後提供；Claude 不代為轉檔、壓縮或批次處理圖片，以避免額外 token 消耗。WebP／SVG 也要確認實際容量。

貼給 AI：

請完成並自行檢查完整桌機首頁，開啟目前有效版本的預覽。
從頁首到頁尾確認構圖、圖片、文案、動畫、導覽與回到頂部。
一起準備 Cookie 提示與可閱讀的隱私權政策頁；政策草稿請標示待客戶確認。
請列出待補資料、暫代內容、未完成功能及實際測試範圍。
切版完成後請提醒我檢核專案檔案大小，列出非 WebP／SVG 圖片的路徑與大小，由我自行轉檔；Claude 不代為處理。

做到這裡再往下： 你已實際看過整頁並操作，再回覆「首頁（填版本）的桌機畫面與動態確認」。政策內容由客戶確認；手機未做就不能記為完成。

第 8 步｜延伸內頁

提供內頁清單與內容，AI 先盤點頁型，選代表頁給你確認再展開同類頁。關於我們、服務、ESG 等核心頁要有完整構圖與閱讀節奏；查閱與操作頁優先清楚穩定。

首頁與內頁共用同一套導覽、頁尾及回到頂部。客戶要自行更新的文字、圖片與清單由 AI 先盤點，只有用途不明或影響設計的部分再問你。

貼給 AI：

桌機首頁已確認，接著製作這些內頁：（填頁面清單）。
資料在：（填位置）。
請先盤點頁型、內容及平台可支援功能，選代表頁給我確認後再展開同類頁。
沿用確認的視覺、共用導覽、頁尾與回到頂部，維持整頁設計完成度。
需要客戶自行更新的內容請主動整理，不確定用途的再問我。

做到這裡再往下： 各頁內容正確、風格一致、有實際預覽，且可編輯需求與平台待確認項目都有記錄。

第 9 步｜完成 RWD，再交客戶校稿

本手冊的製作流程包含 RWD（依不同螢幕調整版面）。桌機內部確認後直接接續平板與手機，完成檢查才交客戶校稿，不需要另外開一個工作情境。小螢幕需依內容調整排列、圖片裁切、導覽與動態，不能只把桌機整頁縮小。

貼給 AI：

桌機已確認，現在請製作本案的平板與手機版本。
範圍：（填頁面及約定尺寸，未定尺寸請先提出建議）。
保留確認內容與主要操作，依小螢幕調整版面及動態。
請提供對應預覽，讓我檢查選單、文字、圖片、按鈕及觸控操作。

做到這裡再往下： 約定頁面與尺寸已看過、操作過，文字可讀、按鈕好點、沒有內容裁切或橫向捲軸。沒有驗證的尺寸明列。

第 10 步｜取得外網連結與客戶校稿

  1. 01效率雲開版

    取得本案版號。

  2. 02建立 project

    已經有就沿用。

  3. 03複製切版成果

    放入案件版號資料夾。

  4. 04推到 Git

    依公司教學情況 A。

  5. 05取得外網連結

    效率雲 → 62 DEMO。

桌機與 RWD 完成內部檢查後，依下面流程取得客戶可開啟的外網連結，再提供校稿。

A｜至效率雲開版，取得案件版號

至效率雲，開版本案的 Evomni，取得案件版號。後續的資料夾名稱與 Git 設定依這個版號及公司教學填寫。

B｜在本機建立 project 資料夾

在你的電腦本機建立一個名為 project 的資料夾，專門放靜態切版案件。已經建立過就沿用，不需要再開一個。

這個資料夾是校稿用的本機網站副本，和前面 Google Drive 的案件工作資料夾分開。

C｜建立案件版號資料夾，複製切版成果

在 project 裡新增資料夾，名稱就是案件版號，再將目前要校稿的靜態網站複製進去。首頁、內頁、CSS、JavaScript、圖片與字型等網站所需檔案都要完整複製；客戶資料與提案文件不用放入。

project/
└── （案件版號）/
    ├── index.html
    ├── 其他內頁.html
    ├── css/
    ├── js/
    └── assets/

這是網站檔案的位置示意；沿用本案實際的資料夾與檔名。複製完成後先開啟首頁及內頁，確認圖片、連結與互動正常。

D｜依「情況 A」將專案推到 Git

開啟公司教學 內部 Git 專案空間使用說明（文件 2335），依 情況 A：新網頁建立新專案 執行。

操作位置是本機 project/案件版號/。依文件填入本案資料，按順序完成教學中的三個指令；帳密由你本人輸入。公司 Git 需要在公司網路或 VPN 內操作。

已有 Git 專案、這次只是更新校稿版時，沿用原專案的更新流程，不重複建立新專案。

公司提供的 Apple 捷徑：

  • 取得捷徑 2
  • 取得捷徑 3

依公司教學確認各捷徑的用途與執行順序。

E｜到效率雲「62 DEMO」取得外網連結

三個指令完成、確認 Git 推送成功後，回到效率雲 → 62 DEMO，就能取得本案的外網連結。

用這個連結檢查首頁、內頁與 RWD，確認客戶能正常查看，再將連結提供給客戶校稿。請 AI 在進度中記錄案件版號、外網連結及這次校稿版本。

做到這裡再往下： 客戶能透過 62 DEMO 外網連結查看完整網站，校稿版號與版本已記錄。

第 11 步｜當你收到修改資料時

本機已經有這個專案，就開啟對應資料夾，將修改資料交給 Claude，沿用既有進度與確認版本繼續修改。還沒下載到這台電腦時，先依情況 B 取得專案。

情況 B｜想下載已存在的專案到自己電腦

  1. 開啟 VSCode，按下 Ctrl + Shift + P；Mac 請按 Cmd + Shift + P。
  2. 輸入並選擇 Git: Clone。
  3. 貼上本案的公司 Git 專案網址。
  4. 選擇要存放在電腦裡的資料夾，建議選本機 project。依提示由你本人輸入帳號密碼，完成下載後開啟這個專案。

下載操作可參考 VSCode 官方 Git: Clone 說明。

情況 C｜修改完網頁要同步上傳

修改完成並檢查桌機與 RWD 後，直接請 Claude 幫你提交並 push 到原本的公司 Git 專案，就能更新 62 DEMO 校稿版本。

貼給 Claude：

本案修改已完成，請幫我提交並 push 到原本的公司 Git 專案，更新 62 DEMO 校稿版。
專案資料夾：（填本機 project 裡這個案件的完整路徑）。
請確認這裡是最新的校稿檔案，沿用原本的儲存庫與分支，核對遠端變更並處理可判定的同步問題。
需要登入時讓我本人操作；若有無法判定的衝突，請列出具體差異。
完成後回報推送結果，並記錄這次修改版本與 62 DEMO 連結。

Claude 回報推送成功後，到效率雲 → 62 DEMO 開啟外網連結，確認最新內容與修改結果，再通知客戶繼續校稿。

做到這裡再往下： 修改內容已同步到 62 DEMO 並重新檢查。待客戶確認後，再整理靜態網站交付。

第 12 步｜整理靜態網站交付

客戶確認後，請 AI 整理這一版的靜態網站、素材與交付說明。保留目前有效入口與原始製作檔案，讓接手的人能找到、預覽並維護網站。

貼給 AI：

客戶已確認這一版，請整理靜態網站交付資料。
列出確認版號與版本、62 DEMO 連結、各頁入口，以及 HTML、CSS、JavaScript、素材與字型的位置。
核對缺圖、連結、互動、頁面完整度與 RWD；排除 .DS_Store 等非交付檔案。
記錄預覽方式、AI 已檢查與客戶已確認的範圍，以及仍需補充的資料。
本次只整理靜態網站交付，不自行上傳或部署。

做到這裡再往下： 接手的人能找到確認版網站、素材、預覽與維護說明；未完成項目及負責人清楚列出。

下次繼續／切換工具

回到同一案件資料夾，優先接續原對話。換電腦先等資料同步；換工具或新對話時，讓 AI 讀同一份進度，保留已確認內容。

離開前貼給 AI：

請更新本案進度，記錄目前階段、確認版本、工具授權、素材與預覽位置、已知問題及下一步。
讓另一個工具或新對話讀取後能直接接續，不必重新提案。

接續時貼給 AI：

使用（填 visual-solution-immersive-director／lin-frontend）。
案件資料夾：（填完整路徑）。
請先讀進度與已確認內容，說明目前階段、有效預覽及下一步，不要重新開始。
本次工作：（填要做的內容）。
請沿用既有授權，保留已確認的設計與動態。

做到這裡再往下： AI 接到正確階段及版本。模型選擇由 AI 依當前階段簡短建議；切換前留下進度，不用因換模型重開設計。
