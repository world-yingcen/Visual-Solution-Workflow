先看重點

一個入口，五次確認

整體視覺網站只用一支主 Skill。你不必先想好構圖、動畫或技術解法，AI 會主動推進，只在五個確認點停下來等你判斷。

  • 只有一個入口

    visual-solution-immersive-director 同時負責設計、素材、切版與自查，不分派角色，也不會自動開多個 AI 代理。

  • 你判斷，AI 製作

    你提供資料、做確認與取捨；整理資料、提案、做素材、實作、實看與修正都由 Skill 主動完成。

  • 2560×1280 桌機優先

    構圖、裁切、字級與捲動節奏都在這個尺寸驗收。平板與手機（RWD）要另外提出才會做。

  • 「好」只確認看到的

    靜態視覺通過不代表動態通過，片段通過也不代表整頁通過。

套件內容

裝一次，得到 11 支 Skill

安裝程式會一起裝好主 Skill、8 支 GSAP 技術參考與 2 支 Eagle 工具。平常只需要叫主 Skill，其他的會在需要時自動讀取。

所有案件從這裡開始

整體視覺網站設計與製作

visual-solution-immersive-director

整體視覺網站的唯一主入口：內容盤點、方向與視覺提案、動態分鏡、核心片段試做、完整桌機首頁，到確認後的內頁延伸。

收藏案例時叫它

案例分析與 Eagle 整理

eagle-visual-solution-curator

把喜歡的網站、截圖或影片，整理成可貼進 Eagle 的名稱、分類、標籤與備註。

不用叫，主 Skill 自動讀取

gsap-coregsap-timelinegsap-scrolltriggergsap-performancegsap-pluginsgsap-utilsgsap-reactgsap-frameworks

做捲動連動、時間軸或效能調整時按需讀取；安裝 Skill 不會另外安裝 GSAP 套件。

通常不用叫

Eagle 資源庫操作

eagle

搜尋、資料夾與標籤操作，其他 Skill 需要時會讀。也可以直接請它搜尋 Eagle。

適合

  • 整體視覺網站：以客戶既有品牌內容為主體，做專屬構圖、影像整合與有目的的互動。
  • 忠實重建：指定的來源就是答案，逐項對照還原。
  • 指定特徵轉譯：只取參考網站的某個特徵，其餘原創。
  • 同案內頁：首頁確認後，延伸到內頁。

不適合

  • 高效方案案件：母版、流程與產圖管道都不同，請用高效方案的 Skill。
  • 與案件無關的一般切版或小幅 CSS 修改：直接請 AI 修改即可，不必啟動整套流程。
  • 還沒有品牌母題的品牌賦能案：先完成品牌概念與專屬素材，再回來做網站。

安裝

三個指令完成安裝

把套件 clone 到本機後，在套件資料夾開啟終端機，依序試跑、安裝、檢查狀態，再重新開啟 AI 工具。

人工｜安裝前準備

需要的環境

  1. Python 3.9 以上在終端機輸入 python3 --version 確認版本。
  2. GitMac 輸入 git --version，沒有的話執行 xcode-select --install。
  3. 取得套件把套件的 Git 專案 git clone 到本機固定資料夾（網址由維護者提供）。每台電腦各一份，不放雲端硬碟：雲端硬碟不會幫你 git pull，兩台電腦同步同一個 .git 還會弄壞它。
  4. 用到 Eagle 才需要Eagle 已開啟並啟用 MCP 外掛（本機 API，埠號 41596），以及 Node.js。
  1. 01試跑python3 install.py --dry-run

    只列出會做什麼、不寫入。第一次安裝會看到 11 行 [新增]。

  2. 02安裝python3 install.py

    在 ~/.claude/skills 建立 11 支 Skill 的捷徑，指向 clone 的資料夾。

  3. 03檢查python3 install.py --status

    每一支都是 [正常]，最後一行是「主 Skill 正常，可以使用。」

  4. 04重新開啟

    重新開啟 Claude Code，技能清單就會出現這些 Skill。

Codex 使用者

在指令後加 --target ~/.codex/skills，例如 python3 install.py --target ~/.codex/skills，完成後重新開啟 Codex。

捷徑指向 clone 的資料夾

資料夾放定位後不要搬、不要放雲端硬碟，搬走捷徑就斷了。Windows 用複製安裝的人，每次更新後要再跑一次 python3 install.py。

請裝整包

用安裝程式一次裝好。只手動搬主 Skill 資料夾，會缺少 GSAP 技術參考。

更新與移除

更新到新版

怎麼更新
每次開始或接續案件時，Skill 會自動在套件資料夾執行一次 python3 install.py --update（git pull）保持最新；沒網路或失敗就照現有版本繼續並告訴你。想自己更新也是同一個指令。捷徑安裝立即生效，複製安裝會自動同步。
沒有 git 時
向維護者拿分享包 zip，解壓後執行 python3 install.py --copy。

步驟
先 python3 install.py --status 核對，再執行 python3 install.py --uninstall。

開案前準備

資料放進同一個資料夾就好

不必先重新命名或分類。案件資料夾放在 Google 雲端硬碟的同步資料夾裡，公司和家裡都接得上，不用搬檔案；做完再推到 git。盤點與歸位由 Skill 處理，要搬移檔案前會先列出計畫給你確認。

  1. 01
    客戶資料

    網站製作 MEMO 與需求單放線上文件的連結（例如一個 TXT 寫上連結），不放 PDF；另附訪談紀錄、產業背景、既有網站網址。

  2. 02
    品牌素材

    Logo、CIS 或品牌規範。沒有 CIS 也能開始，Skill 會先提建議與樣張給你判斷。

  3. 03
    內容與素材

    已確認的文案與網站架構、圖片、影片、型錄。原始檔保留原件。

  4. 04
    不能改的部分

    角色、產品外型、包裝、建築、主視覺、識別色與材質。先講清楚，Skill 只會加強呈現，不會重新設計。

  5. 05
    參考網站（選用）

    一定要說清楚用途。同一個網址，說法不同，做法就完全不同，見下方三種說法。

參考網站的用途，決定整個案子走哪條路

照著做

忠實重建
首頁照這個網站忠實重建，內容換成本案

來源就是答案，不重新發想，逐項對照還原；缺少的來源素材會標出來，不會默默替換。

只要某個特徵

指定特徵轉譯
只取這個 Banner 的照片錯位疊層，其他原創

列出要保留、要轉換、開放原創的部分，只把約定的特徵轉進本案。

當作品質標準

原創
參考它的完成度，方向依品牌由你提案

參考只是證據，方向從本案品牌與內容發展，不套用參考網站的風格。

只說「參考這個」時，Skill 會先整理可保留與可改的部分再跟你確認，不會自己決定怎麼混用。

啟動與接續

在案件資料夾說第一句話

在 Claude Code 把工作資料夾設為雲端硬碟裡的案件資料夾；用終端機的話，先 cd 到案件資料夾再輸入 claude。在 Skill 套件資料夾裡，預設只維護 Skill 本身。

Skill 每一輪會做什麼

  1. 01更新套件、讀案件現況

    先在套件資料夾跑一次 --update 保持最新，再讀既有檔案、進度、已確認的決策與工程限制。已有確認就沿用，不重問。

  2. 02判斷分級與模式

    確認是整體視覺、需要品牌賦能還是忠實重建，找出目前該做的階段。

  3. 03只讀需要的規則

    依階段讀取對應的規則文件，不一次載入全部。

  4. 04做出看得到的東西

    提案是可觀看的畫面，試做是可操作的瀏覽器預覽，不是只交文件。

  5. 05回填並決定續跑

    決策寫回正本與進度檔。已授權範圍連續做完，遇到確認點才停。

接續既有案件

繼續這個案件

Skill 會讀案件根目錄的 README.md 與 experience-status.md，從上次停下的地方往下做，不重新提案。

換電腦、換模型或隔很久再做之前，先請它「更新進度檔」，確認已確認項目、素材與預覽路徑、已知問題與下一步都已寫入。換電腦時，先等雲端硬碟同步完成再說「繼續這個案件」，不然 Skill 讀到的是舊檔。

流程與確認點

你只要顧這 5 個確認點

Skill 依序推進，只在琥珀色的確認點停下來等你。忠實重建的案子跳過方向確認，視覺與動態提案改成來源對照與還原分鏡。

  1. 01人工開案

    提供案件資料夾、客戶資料、CIS 與素材。

  2. 02Skill盤點與模式判斷

    分開事實、推論與缺口，決定原創、特徵轉譯或忠實重建。

  3. 03Skill提 2–3 個方向

    概念真正不同，附評分與推薦。

  4. 04人工① 方向確認

    選定一個，或授權 AI 依推薦代選。

  5. 05Skill視覺提案

    用色比例、字體、ICON、人物與 2560×1280 關鍵構圖。

  6. 06人工② 視覺確認

    確認視覺，不等於確認動態。

  7. 07Skill動態提案與分鏡

    起始、過程、結束，轉場與回捲。

  8. 08人工③ 動態確認

    先看分鏡，確認後才進實作。

  9. 09Skill核心片段試做

    素材、規格與可操作預覽，在 2560×1280 自查。

  10. 10人工④ 核心片段確認

    實際捲動與操作，不是看截圖。

  11. 11Skill完整桌機首頁

    全頁內容、動態節奏、Nav、Footer 與 CTA，自查到頁尾。

  12. 12人工⑤ 完整首頁確認

    整頁一次確認。

  13. 13人工提出內頁

    代表頁先確認，再展開同類頁。

  14. 14人工另行授權 RWD

    不在預設流程，要做時另立範圍。

人工確認點Skill 自動推進你提出後才開始

開案時 Skill 會先問你是否授權 Codex 執行已定規格，以及產圖方式，答案記在進度檔。核心片段確認後，若已授權且場景表、規格與素材齊全，完整首頁與內頁的實作可交給 Codex，Claude 做最後實看。產圖預設由 Claude 操作 ChatGPT 網頁生成、你下載成品，不用 Codex 產圖。這是建議分工，不是強制。

確認與回饋

你說「好」的時候，確認了什麼

每個確認點分開記錄版本與範圍。回「好」只會讓當下展示、而且你明確確認的內容變成已確認。

  1. 01五個確認點分開算

    方向、視覺、動態、核心片段、完整首頁各自記錄版本與範圍。

  2. 02只涵蓋當下展示的

    還沒展示過的結果不算確認；靜態視覺不代表動態，片段不代表整頁。

  3. 03中間不會一直問你

    素材處理、細節、程式修正與重新檢查，會在已授權範圍內連續做完。

  4. 04回饋先寫回正本

    像「人物不要拆」這類回饋會變成素材約定，寫進正本後才實作，不會只留在對話裡。

  5. 05三種狀態分開記

    AI 自查通過、AI 自評、你的確認是三件事；分數不代表完成。

  6. 06做不出來就修到成立

    不會包裝成「完成，之後可優化」。同一原因修兩輪沒改善就換做法；要改已確認方向時，會帶方案來問你。

回饋怎麼給

講清楚三件事，能附參考或數值更好。

哪裡位置或區塊例：A 到 B 的換層
看到什麼實際的問題例：要捲很久才換，感覺黏住
想要什麼期望的結果例：縮短到一個畫面內換完

合起來說：A 到 B 的換層要捲很久才換，感覺黏住，縮短到一個畫面內換完。

實測案例學到的說法

品牌個性抓不到，例如不夠可愛

直接給字體與參考網站當基準；品牌個性很難讓 AI 自己判斷。

區塊之間太平、沒有重點

提供 CIS 輔助圖形的應用頁當參考，要求區塊之間加上銜接。

編排重複，好幾段都是左文右圖

指出哪幾段重複，要求每段有自己的構圖邏輯。

常見問題

開始之前，大家最常問的

沒有 CIS 可以開始嗎？

可以。Skill 會盤點 Logo、產品、官網與照片裡的品牌線索，針對缺的部分提出具體建議與樣張，經你確認後作為本案網站視覺約定。

為什麼只做 2560×1280？

這是第一階段的驗收尺寸，構圖、裁切、字級、捲動距離與效能都在這個尺寸實看。RWD 要另外提出；本案需要其他桌機尺寸時可以直接指定。

可以不做片段，直接要完整首頁嗎？

可以明確要求。Skill 會先完成全頁構圖、素材與動態強弱的規劃再實作，不會只做 Banner。

可以沿用高效方案的母版或案例嗎？

不能直接沿用。高效方案的母版策略、產圖管道、案例結論與額度換算都不適用，歷史案例只供查閱。

會自動叫 Codex 或開多個 AI 代理嗎？

不會自動叫。每個案件開始時 Skill 會先問你要不要授權 Codex 執行已定規格，以及產圖方式，答案記在進度檔，之後不重問；沒授權就全部由 Claude 做。建議的分工是：Claude 負責到核心片段確認的設計工作與之後每一輪的實看；核心片段確認後，場景表、規格與素材齊全時，可交給 Codex 執行完整首頁與內頁，Claude 只做最後實看。產圖不走 Codex：由 Claude 操作 ChatGPT 網頁生成、你下載成品。

製作時一直跳出權限詢問，可以減少嗎？

Claude Code 可選用 python3 install.py --case 案件資料夾路徑，在該案件建立 .claude/settings.json，讓檔案修改與終端機指令不再逐項詢問；強制推送、git reset --hard，以及對根目錄或家目錄執行的 rm -rf 仍會擋下。已有設定檔時不會覆蓋，也不影響流程中的確認點。

換電腦或換模型要注意什麼？

先請 Skill 更新 experience-status.md：目前階段、已確認與未確認項目、不可改的內容、素材與預覽路徑、動態規格、已知問題和下一步。接手時說「繼續這個案件」即可；換電腦時等雲端硬碟同步完成再開始。

覺得不對，但說不出哪裡不對？

請它「先自查，列出目前最弱的三處並修正」，再從修正結果往下討論。
