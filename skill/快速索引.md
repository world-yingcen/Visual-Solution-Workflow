[教學入口：layout 第一次製作完整流程／依情境](index.html)

更新：2026-10-21

先選你目前的情境，再準備資料、複製指令開始。每次都提供最新案件檔案或已授權的可讀取來源，讓 Claude 先讀既有成果與確認紀錄。

## 1｜靜態頁面需要修改資料時

處理客戶回饋、內容替換、版面與互動問題，保持其餘確認成果。

已有這個專案時，將最新網站檔案、進度與修改資料提供給 Claude App，沿用確認版本繼續修改。還沒下載到這台電腦時，先依情況 B 取得專案。

### 情況 B｜想下載已存在的專案到自己電腦

1. 開啟 VSCode，按下 **Ctrl + Shift + P**；Mac 請按 **Cmd + Shift + P**。
2. 輸入並選擇 **Git: Clone**。
3. 貼上本案的**公司 Git 專案網址**。
4. 選擇要存放在電腦裡的資料夾，選本機 `project`（記得前面有建立的那個 `project` 資料夾嗎）。
5. 本人輸入帳號密碼（毓祥有私訊你），完成下載後開啟這個專案。

詳細操作請看公司教學 [內部 Git 專案空間使用說明（文件 2335）](http://posthub.miracle-single.tw/docsys/#/articles/publish/2335)，找到 **「情況 B｜想下載已存在的專案到自己電腦」**，依教學下載既有專案，不重複執行新專案初始化。

### 請 Lin-EVO 處理修改

連結專案後，Lin-EVO 每輪工作前會先確認 Git 遠端狀態，回報是否已同步、有更新要拉取，或有尚未推送的提交。可以安全更新時才更新；有未提交修改或雙方都有新提交時，先問你再處理。不會自行 commit 或 push。若沒有 Git 工具或連線失敗，會說明尚未確認最新版，並先問是否需要帶著操作。

1. **連結切版檔案：** 將本機 `project` 裡本案的切版檔案連結到 Claude App，確認 Claude 能實際讀取；若目前無法連結，改為上傳本輪需要的檔案。
2. **提供修改文件：** 把客戶的修改文件、截圖與新素材交給 Claude，請它先讀完並整理修改項目，先不要動手修改。
3. **讀取最新版 Lin-EVO：** 再請 Claude 讀取維護者已更新的 Lin-EVO 規範，依修改文件處理，保留其他已確認的設計與功能。

**檔案與修改文件都提供後，貼給 Claude：**

```text
請先讀取已連結的切版檔案與我提供的修改文件。
再讀取最新版 Lin-EVO Skill，依修改文件協助修改，保留其他已確認的設計與功能。
完成後檢查相關頁面與 RWD，提供預覽；先不要 push。
```

### 情況 C｜修改完網頁要同步上傳

**注意：** 網站已發布到 .62 後，修改檔案並 **push**，待發布更新完成，客戶透過原本的連結就能看到修改。

直接在已連結的原 Git 專案內修改，不需要另外下載或搬回檔案。修改與檢查完成後，Claude 先問你是否需要帶著操作 Git，確認本次提交與推送範圍後，再 commit 並 push。

確認實際推送成功後，到**效率雲 → 62 DEMO** 開啟外網連結，確認最新內容與修改結果，再通知客戶繼續校稿。

## 2｜EVO首頁已完成，要接續做內頁

首頁已完成並確認，現在要接續製作內頁。沿用確認的視覺與工程，不重做首頁。

### 先取得專案｜Git: Clone 流程

這台電腦還沒有專案時，先依下列步驟下載；已有專案就直接開啟，不用重複 Clone 或初始化。VSCode 左下角更新／同步的數字可作為提醒，但沒有數字不代表已確認遠端最新。

1. 開啟 VSCode，按下 **Ctrl + Shift + P**；Mac 請按 **Cmd + Shift + P**。
2. 輸入並選擇 **Git: Clone**。
3. 貼上本案的**公司 Git 專案網址**。
4. 選擇要存放在電腦裡的資料夾，選本機 `project`（記得前面有建立的那個 `project` 資料夾嗎）。
5. 本人輸入帳號密碼（毓祥有私訊你），完成下載後開啟這個專案。

詳細操作請看公司教學 [內部 Git 專案空間使用說明（文件 2335）](http://posthub.miracle-single.tw/docsys/#/articles/publish/2335)，找到 **「情況 B｜想下載已存在的專案到自己電腦」**。

### 接續製作內頁

連結專案後，Lin-EVO 每輪工作前會先確認 Git 遠端狀態，回報是否已同步、有更新要拉取，或有尚未推送的提交。可以安全更新時才更新；有未提交修改或雙方都有新提交時，先問你再處理。不會自行 commit 或 push。若沒有 Git 工具或連線失敗，會說明尚未確認最新版，並先問是否需要帶著操作。

1. **連結檔案、提供內頁資料：** 將原專案的切版檔案連結到 Claude，確認能讀取，再把內頁清單、文案與素材交給它，請它先讀完。
2. **請 Lin-EVO 製作內頁：** 讀取最新版 Lin-EVO Skill，依照已確認首頁的風格與元素製作內頁，沿用共用導覽、頁尾，不重做首頁。
3. **提供已確認的系統範本：** 如果你已經確定 EVO 有適用的範本，直接提供範例網站網址與要參考的頁面，明確告訴 Claude「這是 EVO 系統範本，請參考它的結構與版型切版，並套用本案首頁的風格與元素」。
4. **組長看稿：** 切版與 RWD 檢查完成後，先交組長看稿；有調整就修改，確認後再進行下一步。
5. **Git commit、push：** 沿用原 Git 專案提交並推送，不另開專案。Claude 先問是否需要帶著操作，並確認本次要 commit、push 後再進行；推送後到 62 DEMO 檢查最新畫面。

**連結專案並提供內頁資料後，貼給 Claude：**

```text
請先讀取已連結的首頁檔案並查看畫面，了解配色、字型、標題層級、間距、按鈕、圖片與互動風格，以及共用導覽和頁尾。
再讀取最新版 Lin-EVO Skill 與我提供的內頁資料，沿用首頁的風格與元素製作內頁，不重做首頁。
若我有提供並註明「EVO 系統範本」的網站，請參考指定頁面的結構與版型切版，套用本案風格；沒有提供就依內頁內容安排。
```

## 3｜專案完成的EVO高效行銷方案，設計師優化

專案提供已完成網站的 ZIP，由 Lin-EVO 依規範檢查、整理檔案，再由設計師確認功能與低級錯誤，確認後發布到公司 Git。

### 接收 ZIP，請 Lin 檢查與整理

1. **專案提供 ZIP：** 取得網站 ZIP、網站代號與需調整的事項，保留原始 ZIP。解壓縮後將網站檔案連結到 Claude，確認它能讀取。
2. **Lin 依規範檢查：** 先讀取最新版 Lin-EVO Skill，檢查檔案結構、HTML／CSS／JavaScript、素材路徑、共用元件與 RWD，整理檔案並修正問題；保留原本的版型與功能，不重新設計。
3. **設計師確認：** 實際開啟首頁與內頁，確認選單、連結、按鈕與表單等功能，再檢查錯字、漏字、破圖、跑版、錯誤連結與手機橫向捲動等低級錯誤。圖片也要處理：請 Lin 列出圖片格式與檔案大小，由設計師將適合的點陣圖片轉成 WebP（SVG 保留），依實際顯示尺寸縮圖並壓縮，確認畫質、單張大小與整體專案容量；替換後請 Lin 更新引用路徑並檢查有無破圖。有問題就請 Lin 修正並重新檢查，確認後才發布。

**檔案提供後，貼給 Claude：**

```text
這是專案提供的 EVO 高效行銷網站，請先讀取檔案與最新版 Lin-EVO Skill。
依規範檢查並整理檔案，修正程式、素材路徑、版面與 RWD 問題，保留原本的版型與功能。
完成後提供預覽與檢查結果，讓我確認功能與低級錯誤；先不要 commit、push 或發布。
```

### 確認後，依 Git 流程發布

Claude 可以帶著操作，但要先問你是否需要協助，並確認本次提交與推送範圍。已有 Git 專案就沿用，不重複初始化；只有 ZIP、不確定是否已有 Git 專案時，先向專案確認。

1. **確認網站代號：** 到效率雲確認本案開版資料與網站代號；已有開版就沿用，不重複開版。
2. **準備本機資料夾：** 沿用本機 `project`，沒有才建立。新 Git 專案將整理好的網站內容放在 `project/網站代號/`，`index.html` 直接在該資料夾內，不多包一層 ZIP 資料夾；只放網站製作檔案，不放帳密或客戶原始文件。
3. **用 VSCode 開啟：** 將網站代號資料夾拖進 VSCode。若已有 Git 專案，先由 Lin 確認遠端狀態，再核對本次 ZIP 與現有檔案的差異，不整包覆蓋既有修改。
4. **新專案首次發布：** 開啟 [內部 Git 專案空間使用說明（文件 2335）](http://posthub.miracle-single.tw/docsys/#/articles/publish/2335)，在 VSCode 開啟終端機，依「情況 A：新網頁建立新專案」填入本案資料，逐一執行三個指令，成功後才執行下一個，直到發布到 .62 的指令完成。已有 Git 專案跳過這一步。
5. **Commit、push：** 首次發布依教學需要產生一次變更時，可請 Lin 確認一段不影響功能的普通 HTML 說明註解再刪除；不刪系統標記或版權聲明。接著到 VSCode「原始檔控制」，檢查差異、暫存本次變更、填寫提交訊息並 commit，再 push。已有 Git 專案直接提交本次確認的修改，不需為此刪註解。
6. **確認 62 DEMO：** 推送成功後，回效率雲本案開版位置取得 62 DEMO 連結，打開檢查最新內容、圖片、功能與 RWD；仍是舊畫面時先查發布狀態，不當成已完成。
7. **留下交接網址：** 開啟 [GitLab 切版專案列表](http://192.168.168.134/client-html-demo/)，找到網站代號，點選 **Code → Clone with HTTP**，記錄 Git 專案網址與 62 DEMO 預覽連結，供後續修改與交接使用。

公司 Git 需要公司網路或 VPN；帳號密碼由你本人輸入（毓祥有私訊你）。已發布到 .62 的網站，push 並完成更新後客戶就看得到修改。

## 4｜靜態頁面轉 EVO

> **重點：已轉 EVO 的案件，原 Git 專案視同廢棄，任何後續修改請直接至 EVO 處理，不再修改或推送原 Git 專案。**

### 先取得專案｜Git: Clone 流程

這台電腦還沒有專案時，先下載；已有專案就直接開啟，不重複 Clone 或初始化，並先確認遠端是否有更新。

1. 開啟 VSCode，按下 **Ctrl + Shift + P**；Mac 請按 **Cmd + Shift + P**。
2. 輸入並選擇 **Git: Clone**。
3. 貼上本案的**公司 Git 專案網址**。
4. 選擇本機 `project` 資料夾（前面已建立的那個，不用重複建立）。
5. 本人輸入帳號密碼（毓祥有私訊你），完成下載後開啟這個專案。

Git 操作可參考 [內部 Git 專案空間使用說明（文件 2335）](http://posthub.miracle-single.tw/docsys/#/articles/publish/2335)中的「情況 B｜想下載已存在的專案到自己電腦」。

### 連結檔案，請 Miffy 轉成 EVO

將本案靜態網站的完整檔案連結到 Claude，確認它能讀取，再呼叫 Miffy-EVO，告訴它這個靜態網站要轉 EVO。

**貼給 Claude：**

```text
請使用 Miffy-EVO，將已連結的靜態網站轉成 EVO「整站匯入」可用的 ZIP。
請先讀取網站檔案與 Miffy-EVO 規範，保留已確認的畫面、功能與 RWD，完成轉換、檢查並提供 ZIP。
```

### 到 EVO 後台整站匯入

1. **開啟案件後台：**登入這個案件的 EVO 後台，確認網站代號正確，找到**「整站匯入」**功能；找不到時請工程師確認。
2. **上傳 ZIP：**直接上傳 Miffy 處理好的 ZIP，程式會檢查有無錯誤。若後台已有內容，先備份並確認這次匯入會影響的頁面。
3. **有錯誤就回 Claude 修復：**將錯誤報告或完整錯誤訊息交給 Claude，請 Miffy 修正、重新打包，再上傳新的 ZIP 檢查。重複到後台顯示 **0 錯誤**；若因缺檔或平台問題無法排除，請補資料或找工程師協助，不跳過錯誤。
4. **完成匯入：**0 錯誤後，依後台提示完成匯入並確認成功；若有警告也要確認內容，不能只看到 ZIP 上傳完成就當成匯入成功。

**有錯誤時，把報告一起交給 Claude：**

```text
這是 EVO「整站匯入」的錯誤報告，請使用 Miffy-EVO 依報告修復，重新檢查並提供新的 ZIP，讓我再次上傳。
```

### 匯入成功後，逐頁檢查

到各個頁面檢查文字、圖片、版型、導覽、連結與互動，以及桌機、平板和手機畫面。試著修改文字、換圖並儲存，重新開啟確認內容仍保留；有差異就回 Claude 修正再檢查。匯入成功不等於正式發布。

## 5｜下班換電腦怎麼接續

離開前先整理 handoff（接續交接），一定要完成 commit 並確認 push 成功，換電腦再取得最新版本，讓 Claude 先讀交接、接著做。

### 離開前｜整理交接並 commit、push

請 Claude 更新原本的進度檔，記錄做到哪裡、哪些已確認、還有哪些問題與下一步。將交接紀錄與本次修改的網站檔案、必要素材一起納入原 Git 專案，檢查提交內容不含帳密或其他機密，再 commit 並 push。確認推送成功後才算完成離開前的交接；推送失敗就先處理，不略過。

**離開前貼給 Claude：**

```text
我要下班換電腦接續，請整理本案 handoff。
更新原本的進度檔，記錄目前階段、確認版本、檔案位置、已知問題與下一步。
請整理交接紀錄與本次修改的網站檔案、必要素材，檢查不要包含帳密或其他機密。
這次需要完成 commit 並 push，請先問我是否需要帶著操作 Git，再依確認的範圍完成；確認推送成功後，告訴我分支、版本與換電腦後先開哪個檔案。
```

### 換電腦後｜取得同一版本

1. **用 Git 取得：** 另一台電腦還沒有專案時，用 Git: Clone 下載；已有專案就開啟原專案，確認沒有未處理的本機修改後 pull 最新版本，不重複 Clone。核對分支與離開前 push 成功的版本；有衝突時先處理，不直接覆蓋。
2. **連結給 Claude：** 將交接紀錄與同一版本的案件檔案連結到 Claude，確認它能讀取。檔案缺漏或兩台版本不同時，先請它列出差異，確認後再接續。

### 接續工作｜Claude 先讀交接再繼續

**接續時貼給 Claude：**

```text
我要接續這個案件，請先讀取已連結的 handoff 交接紀錄與案件檔案，確認版本一致。
簡短告訴我目前做到哪裡、哪些已確認、還有哪些問題與下一步，再使用目前階段適用的 Skill 接續。
保留已確認的設計與動態，不重新提案；若缺檔或版本不同，先列出差異，不直接覆蓋。
```

## 6｜Webtech2 首頁完成，要改EVO

2. 取得這個案件的**網站代號**。
3. 在本機 `project` 資料夾內，新增以**網站代號**命名的資料夾；已有同名案件資料夾就沿用。
4. 將這個案件資料夾連結到 Claude，並提供 Webtech2 已完成的網站網址。
5. 在對話貼上下方指令，請 Lin-EVO 依原網站重新切版首頁。

**貼給 Claude：**

```text
使用 Lin-EVO，依最新 Lin-EVO 規範重新切版本案首頁。
Webtech2 已完成網站：（貼上網址）
請依原網站的畫面與互動重切首頁，將檔案存放在已連結的案件資料夾。
```

### 切版完成｜逐一比對原網站與 RWD

Lin 切版完成後，再提供原本的 Webtech2 網站連結，請它在相同視窗尺寸下逐區比對桌機、平板與手機版，找出樣式與互動差異並修正。

**貼給 Claude：**

```text
請使用 Lin-EVO，逐一比對目前切版成果與原本的 Webtech2 網站：（貼上網址）。
桌機、平板與手機版都要用相同視窗尺寸比對，包含版型、配色、字型、字級、間距、圖片裁切、導覽、按鈕與動態互動。
請列出差異並修正，保留原網站的設計；修正後重新比對，提供預覽讓我人工確認。
```

### 人工確認與調整

設計師實際查看桌機、平板與手機版，確認樣式、圖片、功能與 RWD。有差異就提供截圖或操作說明，請 Lin 調整並重新檢查；人工確認完成後，再進行 Git 發布。

### 確認後，依 Git 流程發布

Claude 可以帶著操作，但要先問你是否需要協助，並確認本次提交與推送範圍。沿用前面建立的網站代號與案件資料夾；已有 Git 專案就沿用，不重複初始化。

1. **確認檔案：** 網站內容放在 `project/網站代號/`，`index.html` 直接在該資料夾內；檢查只包含網站製作檔案，不放帳密或客戶原始文件。
2. **開啟 VSCode：** 用 VSCode 開啟網站代號資料夾。已有 Git 專案時，先請 Lin 確認遠端狀態，有衝突先處理，不直接覆蓋。
3. **首次發布：** 新 Git 專案依 [內部 Git 專案空間使用說明（文件 2335）](http://posthub.miracle-single.tw/docsys/#/articles/publish/2335)的「情況 A：新網頁建立新專案」，填入本案資料並依序完成初始化與 .62 發布設定；已有 Git 專案跳過初始化。
4. **Commit、push：** 在 VSCode「原始檔控制」檢查差異、暫存本次變更、填寫提交訊息並 commit，再 push，確認實際推送成功。
5. **確認 62 DEMO：** 回效率雲取得本案 62 DEMO 連結，檢查最新畫面、功能與桌機／平板／手機版，並記錄 Git 專案網址與預覽連結。

公司 Git 需要公司網路或 VPN；帳號密碼由你本人輸入（毓祥有私訊你）。
