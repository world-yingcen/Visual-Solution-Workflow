# Mode Routing: CREATE vs RECREATE

## Purpose

Choose the correct operating mode before creative or implementation work begins. The two modes use different levels of creative freedom.

## CREATE Mode

Use when the client needs a new immersive/interactive website, a redesign without a fixed reference answer, or a new experience derived from brand/business inputs.

The reference is evidence, not the answer.

Sequence:
1. Project Intake
2. Client Content Audit
3. Brand Strategy Completion
4. Creative Exploration
5. 2-3 Creative Directions
6. Direction Approval
7. Experience Blueprint
8. Reference Research / DNA
9. Visual System
10. Core-slice storyboard, asset production, and motion architecture
11. Slice-scoped Production Specification + execution brief
12. Build, inspect, refine, and obtain slice approval
13. Expand the proven system into full scene specifications
14. Complete the 2560×1280 desktop homepage and obtain approval
15. Update evidence and production status
16. Desktop inner pages / QA; RWD only when explicitly requested later

Rules:
- Keep Big Idea, Hero, Signature Moment, motion language, visual metaphor, and technical treatment open during Creative Direction.
- Do not inherit a previous project's visual tropes unless the current brand logic independently supports them.
- After direction approval, progressively increase specification density until implementation ambiguity is low.

## RECREATE Mode

Use when the user explicitly wants to recreate, rebuild, reproduce, clone for internal study, or closely match a supplied reference/site/design while preserving its behavior and visual logic.

The reference is the primary answer. Do not invent a new Creative Direction unless the user asks for reinterpretation.

Sequence:
1. Reference / Source Audit
2. Source Quirk Inventory
3. Fidelity Constraints
4. Asset / Font / Media Map
5. Visual + Layout DNA
6. Layer Stack / Positioning Map
7. Section / Scene Behavior Map
8. Motion / Interaction Rules
9. Technical Architecture
10. Slice-scoped Fidelity Specification and implementation
11. Browser comparison, refinement, and slice confirmation
12. Extend fidelity specifications and build the remaining approved scope; validate 2560×1280 desktop fidelity and performance. Responsive behavior is a separate later scope.

Rules:
- Preserve source quirks that create identity, even when they are unconventional.
- Do not "clean up" asymmetry, typography, odd spacing, timing, layering, or interaction behavior without evidence that it is accidental.
- Distinguish exact-fidelity requirements from areas where implementation equivalence is acceptable.
- Record unsupported or unavailable source assets explicitly instead of silently substituting them.
- Do not add new UX, decorative motion, gradients, shadows, interactions, forms, or content that are absent from the approved source unless the user requests them.

## HYBRID Case

If the user wants to borrow a specific reference's structural or motion system but create an original brand expression, use CREATE Mode with a constrained Reference DNA phase.

State clearly:
- what must be preserved from the reference,
- what must be transformed,
- what remains open for original design.

Do not silently treat a reference-led CREATE project as a full RECREATE project.

## Routing Test

Ask internally:

"Is the source/reference itself the approved design answer?"

- Yes -> RECREATE Mode.
- No -> CREATE Mode.
- Partly -> CREATE Mode with explicit reference constraints.
