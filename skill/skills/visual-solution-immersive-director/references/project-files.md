# 整體視覺案件｜PRD 與檔案管理

依使用者指定的 `project-pm` 網站專用規則整合：一案一夾、編號定序、活文件與歷程分離、單一事實來源。由同一任務執行，並非新增 PM 角色或多代理流程。適用客戶案件；本 Skill 套件原始碼維持既有 skills/references 結構。

## 新案件的目錄

案件根目錄放 README.md，頂層資料夾如下：

| 位置 | 用途 |
|---|---|
| `01_專案需求與規劃/` | 設計 PRD、網站架構、視覺提案與體驗藍圖；各類一份有效正本 |
| `02_品牌素材/` | 正式 Logo、CIS、字型與已確認共用品牌資產 |
| `03_頁面製作素材/` | 依網站與区塊順序編號，集中頁面製作及所需資料 |
| `04_型錄與原始素材/` | 客供原始圖片、影片、型錄與來源檔，保留原件 |
| `05_待確認與交接/` | 設計日誌、決策紀錄、待辦與驗收證據索引 |
| `99_歸檔/` | 需要保留但已被取代的提案與試作，不與目前入口混放 |

例如 `03_頁面製作素材/03_01_首頁/03_01_01_Hero/` 集中該區的需求、文案、圖像／影片連結與備註；其他區塊依顯示順序編號。共用素材用相對路徑引用，不每區複製一份。

靜態原型可在頁面目錄下用 `實作/index.html` 搭配 css/、js/、assets/，QA 圖置於頁面 qa/；試驗放獨立試作子目錄。既有框架沿用其 src/public 等工程布局，由 README 和區塊文件連到實際程式，不能為配合資料分類強拆元件或重建框架。

案件資料夾通常放在團隊的 Google 雲端硬碟同步資料夾，讓公司與家裡的電腦接續同一份檔案。README、進度檔與規格裡的路徑以案件資料夾為基準寫相對路徑，不寫某台電腦的絕對路徑；換電腦接續前先確認雲端同步完成，尚未同步完成的檔案不當作最新狀態。Git 推送由使用者在完成階段決定，不因整理檔案自動執行。

## 正本與確認紀錄

- 設計 PRD 記背景、目標、受眾、網站架構、區塊內容、功能、範圍／不做項目、素材來源、里程碑、驗收與待確認事項。未知數據、期限與功能不代填；範本中的 RWD、交易、追蹤及部署不得自動變成案件承諾。
- PRD 管內容／功能／範圍；提案與 Blueprint 管構圖／素材／動態。互相連結，不抄出互相矛盾的第二份規格。
- 文件標版本、狀態、更新日與修訂摘要。小修就地更新，重大方案才另立版本；不用「最終版2」。檔名或版本號不能代替使用者確認。
- 使用者拍板的修改先回填對應正本及決策，再實作；一般錯字／參數細修簡記即可，不新增核准儀式。回饋如「人物不要拆」須成為素材約定，不能只存在聊天裡。
- 收尾更新設計日誌、決策與待辦；已有 experience-status.md 時保留為狀態唯一正本，以相應章節承載這些紀錄並從 README 連入。不要為了文件名稱再複製三份相同內容。整理搬移後可拆分，但只留一份有效狀態。

## README 與日常整潔

README 首屏列目前唯一工作入口及預覽方式、已確認版本／畫面、PRD 與設計正本、狀態文件、未解問題及下一步。區分目前工作版、確認版與案例快照；不要求三者永遠同版。

新增檔案前先決定用途與位置；細修目前工作檔，不每次產出 v9、v10 或新的 override CSS。需要比較的版本放試作區，明列目的和狀態。保留歷程依使用者要求及 Git 可追溯性判斷，不無限製作備份；未獲刪除授權時不刪客戶素材、舊版或疑似重複檔。案例庫快照與工作版分開，不因清理順手覆蓋。

## 整理既有案件

1. 先盤點檔案用途與引用，列現路徑 → 新路徑、目前入口、共用依賴及待判定項目；取得搬移計畫確認後才執行。已明確核准的計畫直接執行。
2. HTML 的 stylesheet/script/src、CSS url()、JS 載入／import、跨頁錨點、預覽伺服器根目錄及案例庫連結都納入检查。檔名含 v3 不表示不用，v8 仍引用的資源不可當舊檔移除。
3. 過時方案與其專用資源依計畫移出活躍目錄；共用資源保留單一來源。同步更新受影響引用、README、規格及證據索引，不保留指向失效路徑的「目前版本」。
4. 比對移動前後清單；必要時以雜湊確認素材無遺失。重新開啟目前頁面檢查資源載入與代表性互動；獨立複核只有實際執行才能記為通過。

純修改本 Skill 不等於已整理客戶案件。新規則在之後新增產出時使用；既有案件尚未迁移時如實標示，不能宣稱已整理。
