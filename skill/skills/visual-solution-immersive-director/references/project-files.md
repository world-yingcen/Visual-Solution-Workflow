# 整體視覺案件｜PRD 與檔案管理

依使用者指定的 `project-pm` 網站專用規則整合：一案一夾、編號定序、活文件與歷程分離、單一事實來源。由同一任務執行，並非新增 PM 角色或多代理流程。適用客戶案件；本 Skill 套件原始碼維持既有 skills/references 結構。

## 案件標準目錄（強制）

整理新案件與既有案件時，一律依下列目錄歸位，不另取同用途名稱，也不以「沿用原位置」免除整理。案件根目錄放 README.md；頂層名稱固定，頁面與區塊子目錄依實際內容延伸。先建立標準目錄，尚未進入的階段可留空，不代表該階段已完成。

例外：已完成首次 Git 發布或已 Clone 的網站，沿用 `project/網站代號/` 的原 Git 工程，不再套一層 `06-切版/` 或重新初始化；原準備資料夾只保留規格與素材來源，不維護第二份有效網站。交接進度沿用 repo 內唯一正本；原本放在外部時，先核對敏感內容與同步範圍，再將適合提交的必要接續紀錄移入 repo 並更新引用，不複製兩份有效進度。私人客供文件仍保留原授權位置，紀錄取得方式而非把內容推上 Git。

| 位置 | 用途 |
|---|---|
| `01_專案需求與規劃/` | 設計 PRD、網站架構、視覺提案與體驗藍圖；各類一份有效正本 |
| `02_品牌素材/` | 正式 Logo、CIS、字型與已確認共用品牌資產 |
| `03_頁面製作素材/` | 依網站與區塊順序編號，集中頁面製作及所需資料 |
| `04_型錄與原始素材/` | 客供原始圖片、影片、型錄與來源檔，保留原件 |
| `05_待確認與交接/` | 唯一進度檔、工程師交接說明、設計日誌、決策紀錄、待辦與驗收證據索引 |
| `06-切版/` | 唯一有效的正式網站工程，包含 HTML、樣式、JavaScript、網站使用素材與必要建置設定；Lin-EVO 在此接續 |
| `99_歸檔/` | 需要保留但已被取代的提案與試作，不與目前入口混放 |

例如 `03_頁面製作素材/03_01_首頁/03_01_01_Hero/` 集中該區的需求、文案、圖像／影片連結與備註；其他區塊依顯示順序編號。共用素材用相對路徑引用，不每區複製一份。

核心片段試作放在對應頁面目錄的獨立試作子目錄，QA 圖置於頁面 qa/；核心片段確認、進入正式切版後，將採用的程式與網站使用素材整合至 `06-切版/`，不留下兩份有效工程。`03_頁面製作素材/` 保留頁面需求、文案與素材來源資料。正式網站的 css/、js/、assets/ 或既有 src/public 等內部工程布局保留在 `06-切版/` 內，不為統一頂層位置強拆元件、改框架或任意改資源檔名。README 和區塊文件連到實際程式與預覽入口。

設計準備資料可放團隊已授權的雲端資料夾；Git 切版工程在本機 project 中以 Git 同步，不靠雲端同步 `.git`。README、進度與規格以相對路徑或已授權的文件入口記錄。換電腦前確認必要資料已可取得；是否完成 Git 交接依下方實際 push 結果判定。

## 離開前交接與換電腦續作

適用於案件續作，不是工程師驗收或 EVO 匯入包。尚未轉 EVO 的 Git 切版案件，換電腦固定流程：**整理交接紀錄與必要檔案 → commit 並 push 成功 → 另一台 Clone／更新同一版本 → Claude 先讀交接再繼續。** 只換對話或模型更新進度即可，不因此要求 push。沒有 Git 的設計準備階段沿用已授權資料同步，不自行初始化；已成功匯入 EVO 的案件以後台為準，原靜態 Git 僅留存查閱，不再修改或 push。

### 1. 離開前整理

- 更新既有進度正本（準備階段在 `05_待確認與交接/`，已進入 Git 工程則在該 repo）；沒有才建立 `experience-status.md`，以「接續交接」章節記錄交接時間、目前階段、已確認與不可改項目、本輪改動、未完成／待確認事項、已知問題、已測與未測範圍，以及下一個具體工作。不另造第二份有效進度。
- 記下 README、設計規格、素材、唯一工程與預覽／啟動方式的相對路徑，以及下一輪使用的 Skill 和工具需求。工具授權只記範圍，不記帳密；換環境後仍需確認工具是否可用。
- 記錄 repo／分支、已確認的工作版本與目前 Git 狀態；盤點下一步需要的工程、素材、依賴清單／鎖定檔、啟動設定與必要交接紀錄。交接提交的 commit ID 以提交後回報為準，不為把自身 hash 寫回文件而反覆提交。

### 2. 確認範圍後 commit 並 push

- 先核對目標 repo、分支及本次檔案摘要，詢問是否需要 Claude 帶著操作；已有明確授權不重問。依 [Git 流程](git-workflow.md) 取得遠端狀態，確認同步安全後提交並推送。沒有 Git 工具就逐步引導使用者操作並回傳結果。
- 提交本次必要工程、素材與經核對的接續紀錄；不把舊 ZIP、快取、node_modules、帳密、token、含密鑰的 .env 或私人客供文件推上 Git。必要機密設定只記名稱與重新設定方式，不記值。避免 `git add -A` 把無關工作一起提交。
- **換電腦交接必須完成 push，不能只 commit 或改交未推送 ZIP。** 推送失敗、認證缺口或衝突時保留工作，列出阻礙並標記交接未完成，不 force push、不自動解衝突、不假稱遠端已有新版。
- 核對 push 成功及遠端分支包含交接提交，回報 repo／分支／commit、交接入口與下一步；未能驗證時如實列待確認。不把 Git 同步當作畫面已驗收或 EVO 已發布。

### 3. 換電腦後先讀再繼續

- 沒有專案才 Clone；已有專案直接開啟，依工作前 Git 檢查安全更新，不重複 Clone 或初始化。確認同一分支已包含交接 commit，不能只看 VSCode 左下角沒數字就判定最新版；必要私人資料另核對原授權入口是否可讀。
- Claude 先讀 README、進度中的「接續交接」與相關確認規格，再確認目前工程、素材與版本相符。遇到較新遠端、兩台都有修改或缺檔時，先列差異確認，不以檔名或修改時間猜誰是有效版本，也不自行刪檔、reset 或覆蓋。版本未確認前只做不受影響的盤點。
- 簡短回報「目前階段、取得的版本、已確認內容、未完成事項與下一步」，接著依原授權範圍續作；不重新提案、不重做確認成果、不因換對話擴大 RWD 或發布範圍。新環境的檔案連結、編譯及預覽需重新確認，原電腦的測試紀錄不等於新環境已測。

## PDF 讀取與暫存

- 盤點案件資料夾及子資料夾時，先只列出 PDF 的檔名、路徑與檔案大小，不先擷取文字、OCR 或渲染頁面。先確認單一檔案大小；無法確認大小時不讀內容。
- **單一 PDF 超過 10 MB（10,000,000 bytes）一律拒絕讀取，即使使用者明確要求、催促或同意 token 消耗，也不例外。** 明確回覆：「這份 PDF 超過 10 MB，依本 Skill 規則不讀取。請直接截圖提供需要的重點，或將重點整理成 Markdown（.md）檔案提供。」不得先讀幾頁、擷取文字、OCR、渲染，或自行拆分／轉檔來繞過限制。保留原檔，於素材清單標記「超過 10 MB／未讀取」，繼續可做的其他工作；日後用到再讀也受此上限限制。
- 未超過上限的 PDF 才詢問：「這些 PDF 需要讓 AI 現在先讀嗎？還是有要用到再讀？」可整批選擇，或指定哪些先讀；已有明確選擇的同批檔案不重複詢問。PDF 可能消耗較多 token，避免不必要的內容載入。
- 使用者尚未回答時不讀 PDF，繼續整理其他資料。選擇「現在先讀」時，只讀指定檔案與本輪需要的內容，不預設整批全文載入。
- 選擇「有要用到再讀」時，將尚未需要的 PDF 集中到 `04_型錄與原始素材/PDF_待用時讀取/`，保留原檔與必要的來源子目錄，避免同名覆蓋；納入既有案件的搬移計畫與引用檢查。已被網站或文件引用且不適合搬移的 PDF 保留原位，在清單標記位置，不破壞既有引用。
- 在 README 或既有素材清單記錄暫存位置與「尚未讀取／用到再讀」狀態，不把未讀內容寫成已分析結論。後續確實需要時，只讀相關檔案或頁面並更新狀態；使用者已選擇用到再讀，不需每次重問。不因暫時不讀而刪除 PDF。

## 正本與確認紀錄

- 設計 PRD 記背景、目標、受眾、網站架構、區塊內容、功能、範圍／不做項目、素材來源、里程碑、驗收與待確認事項。未知數據、期限與功能不代填；範本中的 RWD、交易、追蹤及部署不得自動變成案件承諾。
- PRD 管內容／功能／範圍；提案與 Blueprint 管構圖／素材／動態。互相連結，不抄出互相矛盾的第二份規格。
- 文件標版本、狀態、更新日與修訂摘要。小修就地更新，重大方案才另立版本；不用「最終版2」。檔名或版本號不能代替使用者確認。
- 使用者拍板的修改先回填對應正本及決策，再實作；一般錯字／參數細修簡記即可，不新增核准儀式。回饋如「人物不要拆」須成為素材約定，不能只存在聊天裡。
- 收尾更新設計日誌、決策與待辦；準備階段進度與交接正本放在 `05_待確認與交接/`。已有 experience-status.md 或其他進度檔時保留內容與檔名；進入已發布／Clone 的 Git 專案後，依上方例外沿用 repo 內正本並更新引用。以相應章節承載紀錄並從 README 連入，不維護第二份進度。

## README 與日常整潔

系統檔案（如 `.DS_Store`）的 Git 忽略、解除追蹤與交付排除，依獨立 Lin-EVO 的「實作與校稿」規範，不在本方案另維護共用條文。

README 首屏列目前唯一工作入口及預覽方式、已確認版本／畫面、PRD 與設計正本、狀態文件、未解問題及下一步。區分目前工作版、確認版與案例快照；不要求三者永遠同版。

新增檔案前先決定用途與位置；細修目前工作檔，不每次產出 v9、v10 或新的 override CSS。需要比較的版本放試作區，明列目的和狀態。保留歷程依使用者要求及 Git 可追溯性判斷，不無限製作備份；未獲刪除授權時不刪客戶素材、舊版或疑似重複檔。案例庫快照與工作版分開，不因清理順手覆蓋。

## 整理既有案件

1. 先盤點檔案用途與引用，依標準目錄列現路徑 → 新路徑、目前入口及共用依賴。使用者已要求整理案件時，直接執行可明確判定且不覆蓋檔案的歸位，不再詢問要不要遵守標準；用途不明、同名衝突、巢狀 Git 或外部部署路徑無法安全調整時，保留受影響原檔並列出具體阻礙，繼續其他可整理項目，不宣稱全部完成。不刪除或搬走 `.git` 來強行符合目錄。
2. HTML 的 stylesheet/script/src、CSS url()、JS 載入／import、跨頁錨點、預覽伺服器根目錄及案例庫連結都納入檢查。檔名含 v3 不表示不用，v8 仍引用的資源不可當舊檔移除。
3. 過時方案與其專用資源依計畫移出活躍目錄；共用資源保留單一來源。同步更新受影響引用、README、規格及證據索引，不保留指向失效路徑的「目前版本」。
4. 比對移動前後清單；必要時以雜湊確認素材無遺失。重新開啟目前頁面檢查資源載入與代表性互動；獨立複核只有實際執行才能記為通過。

純修改本 Skill 不等於已整理客戶案件。新規則在之後新增產出時使用；既有案件尚未遷移時如實標示，不能宣稱已整理。
