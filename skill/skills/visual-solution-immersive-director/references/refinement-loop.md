# 缺陷與修正路徑

每輪先記版本、尺寸、互動狀態、預期與實際差異，再處理影響最大的問題。

| 問題 | 先查 | 回到哪裡修 |
|---|---|---|
| 畫面正確卻普通 | 概念與品牌、核心轉變是否有內容意義 | 深化場景；更換已確認概念需提出差異供決策 |
| 主體像貼圖、轉場露底 | 原素材、透視、拆層與位移 | 素材製作與鏡頭適配 |
| 首屏好看，後面掉級 | 字體、影像、構圖密度、UI 語言 | 視覺系統與後續場景 |
| 文字擠、裁切錯 | DOM、computed style、容器、字體載入 | 結構與 CSS |
| 元素退場後出現空白帶 | opacity 隱藏仍占位、grid 列、gap／padding／min-height、pin 容器及 transform | 找出實際占位來源，調整空間交接；不先用負 margin 掩蓋 |
| CTA 與 Footer 黏連或斷開 | 前段結束狀態、容器高度、背景與間距 | 修正兩段邊界與層級，正反捲動及 resize 後重驗 |
| 倒退跳動、割裂、拖沓 | 狀態歸屬、起止位置、重複控制、停留時間 | 動態架構與編排 |
| 掉幀、卡頓、載入久 | performance trace、網路、資源、layout 與 GPU 成本 | 依量測優化，必要時驗證輕量替代 |
| 點不到、拖曳搶捲動 | 疊層、pointer-events、事件／手勢歸屬 | 輸入與圖層管理 |
| 2560×1280 構圖或裁切不成立 | 實際 viewport、縮放、容器、素材安全範圍 | 回到桌機構圖與素材適配 |

觀察 → 根因假設 → 工具或小實驗驗證 → 最小有效修正 → 同條件重驗及相鄰轉場檢查。不要靠記憶比對。

同一根因修正兩輪無改善就重新診斷或換實作方式；這是改變策略的觸發點，不是停止工作的配額。在授權內持續修到可驗收，只有關鍵輸入缺失、工具阻擋或需改已確認設計時帶具體方案請使用者決定。

不得為了分數刪必要內容、取消核心互動或降低品質要求。未解缺陷與未觀察項目如實列出。
