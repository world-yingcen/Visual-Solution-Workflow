# 製作流程與確認點

依既有進度開始，文件可合併，不要求補齊與本輪無關的報告。

各階段產出依 [PRD 與檔案管理](project-files.md) 放置並回填 README；確認與回饋同步到有效正本，實作和舊試作分開。先核對目前入口及其依賴再新增版本，收尾包含檔案整潔與引用有效性。

## CREATE／指定特徵轉譯

1. 整理內容、品牌限制與策略假設。轉譯案列指定保留、轉換及開放部分。
2. 提 2–3 個不同概念、評分理由與推薦。方向經使用者選定或依明確授權代選。
3. 依 [視覺提案](visual-proposal.md) 實看 CIS，展示正式與新增資產、用色比例、字體、ICON、背景圖形、形象／人物與色彩控制、功能圖解及 2560×1280 關鍵構圖。以本案素材與文案呈現 Hero、代表內容段與收尾，附整頁構圖及動態節奏概要；記錄確認版本、待試做與可微調範圍，取得視覺確認。
4. 視覺確認後依 [動態提案](motion-proposal.md) 討論 Hero → 首次轉變 → 代表場景的圖層、觸發、節奏與起始／過程／結束分鏡，取得動態確認。最大風險在別處時可另做獨立技術驗證，但不代表設計確認。
5. 動態確認後製作片段素材與 Production Spec：反向捲動、圖層、操作歸屬與 2560×1280 驗收條件。先不為整站填滿細節。
6. 檢查工程並實作，提供 2560×1280 瀏覽器預覽；灰模技術實驗不能當成視覺片段通過。
7. 實看、實測、修正。核心片段成立並經使用者確認後，把證實的設計語言延伸為整頁規格及桌機首頁。
8. 依 [整頁完整度](full-page-completeness.md) 完成場景表及逐段檢查，保留已確認的區塊順序與任務。完成全部內容、閱讀節奏、導覽與 CTA；以 2560×1280 完成桌機 QA 及使用者確認。
9. 使用者要求內頁後，依 [內頁設計與製作](inner-pages.md) 盤點頁型、確認共通規則與代表頁，再展開同類頁。驗證桌機內容、跨頁路徑、互動、減少動態及效能，交付預覽與啟動方式；首頁確認不等於所有內頁已核准。

Tablet／Mobile／RWD 不在預設流程內；不要提早做可行性版或 fallback。只有使用者後續明確要求時另開階段。使用者明確修改確認節點時依授權。

## RECREATE

有明確忠實重建授權時，不強迫重新發想或新增無必要核准。視覺提案改為來源構圖／CIS 替換對照，動態提案改為實測來源行為／還原分鏡；既有授權可涵蓋確認，但視覺與動態證據仍分開。僅喜歡參考 Banner 的某種質感時，屬指定特徵轉譯，不自動升級成全站重建。

1. 檢查指定來源、頁面及尺寸，記錄可見構圖、資產、動態、特殊行為及未知資訊。
2. 區分精確還原、等效實作與無法驗證，缺來源素材不得靜默替換。
3. 先為高風險片段做 Fidelity Spec、素材處理及實作；只說「參考」且用途不明時先整理保留／可改範圍再釐清。
4. 以 2560×1280 同尺寸比對；動態需操作來源，截圖不能證明時間軸或使用的技術。來源另有明確指定尺寸時，記錄差異並依使用者要求處理。
5. 片段修正確認後擴展 2560×1280 桌機頁並驗證效能。RWD 僅在使用者另行要求時進行；已授權全程自主還原時不新增逐段核准要求。

每次停下更新目前版本、可操作成果、確認狀態、證據、未解問題與下一步。實作檢查通過、AI 自評、使用者確認是不同狀態。
