# 案件時間、Token 與額度紀錄

當使用者要求「記錄時間、Token、消耗百分比、加入案例庫」或同義指令時，讀取本文件並依可查證資料完成；不要只填「待記錄」，也不要把不同計量系統混在一起。

## 固定輸出

至少分開記錄：

- 案件或指定階段名稱、版本與界線。
- 開始、結束時間與時區；elapsed 是牆鐘時間，需註明可能包含討論、等待、產圖及瀏覽器檢查，不等同主動運算時間。
- Codex Token 的起點、終點、差值與來源；若總量包含 cached input，不再把 cached input 重複相加。
- Codex 額度百分比的起點、終點、視窗長度、是否跨重置及計算方式。
- 子階段若包含於總案件，標明「子集合，不重複加總」。
- 未納入的工作，例如後續 Skill 修改、收錄動作、RWD 或下一版本。
- 原始證據或 JSON 路徑，讓之後可以重算。

## Token 計算

優先讀取同一任務原始 `token_count.info.total_token_usage.total_tokens` 的累計值：

`階段 Token = 終點 total_tokens − 起點 total_tokens`

起訖應落在使用者明確開始該案件／階段後，以及該版本首次完成交付前的最近有效快照。若找不到完全貼齊的快照，採最近相鄰快照並標示近似界線。不可用畫面字數、訊息長度或其他案件比例猜 Token。

Token 是案件使用量紀錄，不直接等於 API 費用、Codex 方案百分比或 Claude 額度。

## Codex 額度百分比

百分比優先使用同一額度視窗的 `rate_limits.primary.used_percent` 或 Codex 使用量工具回傳值：

- 未跨重置：`終點 used_percent − 起點 used_percent`。
- 跨一次重置：`100 − 舊視窗起點 + 新視窗終點`。
- 跨多次重置：逐一分段相加；只有每段邊界都有快照才能報總值。
- 只有 Token、沒有同視窗的起訖百分比，也沒有官方固定 Token 上限時，記為「無法由現有證據回推」，不得以 Token 硬除出百分比。
- 百分比是帳戶同期快照差值，可能包含同一期間其他任務；一律標為「約」並揭露此限制。
- 不把 Codex 百分比換算成 Claude Max／20x、ChatGPT 方案、API 費用或其他平台數值。

## 時間界線

優先使用原始事件 timestamp，而不是檔案修改時間。開始點依序採：

1. 使用者明確提供案件路徑並要求開始；
2. 使用者明確要求進入某階段；
3. 最接近實際工作的可證明事件。

結束點採該版本首次完成並交付的事件。後續才發生的 Skill 修改、案例收錄或下一版討論不回灌到舊版數字。若使用者要求「現在為止」則以當次最新快照作終點。

## 案例庫寫法

案例卡預設使用四格：Codex 執行時間、Codex 額度、Claude 執行時間、Claude 額度。方案倍數與每週／其他視窗依本案已確認資料標示，不固定所有案件為 5 倍或 20 倍。

- 時間：例如「約 16 分（追加）」。包含等待時加簡短註記；總案件與追加階段擇本卡範圍呈現。
- 額度：例如「約 3% 每週額度（追加）」。數值需有起訖證據，帳戶同期其他任務可能混入的限制放在鄰近簡短註記。
- 已確認未使用的平台寫「沒有」；有使用但缺紀錄寫「未取得紀錄」，不得混用。
- Token 與起訖、重置、公式等詳細內容保存在 JSON 或可展開明細，預設不擠進四格。使用者明確要求展示 Token 時再列出。

沿用既有案例庫欄位與版型，不另建重複資料來源。

另存機器可讀 JSON，保留 session、timezone、baseline／endpoint timestamp、total tokens、used percent、reset boundary、公式、scope 與 notes。不要只把數字寫在卡片而遺失證據。

## 誠實邊界

精確 Token 差值可以標示為紀錄值；elapsed 與額度百分比依快照界線標示「約」。工具顯示的目前用量不能替代歷史起點。若資料不足，清楚列出已知數值與缺少的端點，不能為了完成案例卡片捏造百分比。
