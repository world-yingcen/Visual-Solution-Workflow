# 動態提案與確認

視覺確認後必讀，先討論再試做。AI 主動提出符合品牌與已確認視覺的推薦，讓使用者看具體分鏡，不要要求使用者自己想動畫。已有明確動態方向就深化；有重大差異時才提供少量可比較的方案。

## 動態提案必備資訊

先在既有 Blueprint 或場景表概述全頁節奏，再深化本輪核心片段分鏡。每個主要區塊及相鄰交界都要交代進入、穩定閱讀、離開與接手方式，涵蓋 Banner 之後到 CTA／Footer；尚未試做的部分標為規劃，不用先做完整首頁。

依內容選擇重點轉場、輕量銜接或安靜閱讀，定義與檢查依 [整頁動態節奏](full-page-completeness.md#整頁動態節奏)。每項動態說明它如何引導視線、解釋內容或延續前後關係；靜態安排則說明閱讀需要。效果名稱與「增加活潑感」不足以代替目的。

| 項目 | 必須說清楚／展示的內容 |
|---|---|
| 設計目的 | 哪個品牌特質、訊息或使用任務需要這個動態；希望訪客先注意什麼、理解什麼。 |
| 參考與證據 | 參考的具體片段與觀察到的行為。區分靜態層次、實測移動、推論與未驗證；不能從截圖斷言視差、WebGL 或動畫時間軸。 |
| 整體動態語言 | 速度、幅度、流動／停留、密度、轉場調性、高潮及安靜閱讀段；哪些元素保持穩定。 |
| 圖層與空間 | 前景／主體／中景／遠景／文字／UI 的排列、遮擋、透明度、景深、光線；各層是否移動、移動方向與相對速度。 |
| 觸發與控制 | 自動播放、捲動連動、進入畫面觸發、hover／pointer／click／鍵盤；可否跳過、暫停、重播。分清滑鼠移動與捲動，不將 hover 設為唯一內容入口。 |
| 起始 → 過程 → 結束 | 每個核心片段至少三張實際畫面或清楚的構圖分鏡，附主體、文字、遮罩、鏡頭的變化。不能只寫「氣泡漂浮」「有層次」。 |
| 節奏與參數 | 自動動畫的時間、延遲、緩動；捲動動畫的距離／進度區間、固定舞台長度、停留點。未實測數值標為試做起點。 |
| 進出與反向 | 如何進入下一場景、回捲如何還原、快速捲動／跳段／resize 是否保有可讀狀態；避免文字同時重疊或空白。 |
| 閱讀與 CTA | 文字何時可讀、停留多久、CTA 何時可用；不可為播放完動畫而延遲正常操作。 |
| 品牌資產邊界 | 哪些是正式圖騰或產品、哪些是效果層；平移、裁切、遮罩、變形是否符合 CIS。原稿不足時列素材需求，不用重繪冒充原圖。 |
| 所需素材 | 去背人物、獨立產品、背景、透明前景、深度圖、影片等各層來源與可用狀態；優先用現有素材，新增需有理由。 |
| 技術與風險 | 用易懂語言說明照片拆層、CSS／SVG、影片或 3D 的選擇，沿用現有工程。指出畫質、效能與素材限制，不用技術名稱代替視覺說明。 |
| 減少動態 | 固定閱讀構圖、停止持續漂浮／視差、保留內容與操作；不將此當成 RWD 階段。 |
| 試做與驗收 | 本輪片段範圍、2560×1280 狀態、重點感受、功能與效能檢查，以及哪些未涵蓋。 |

## 確認與試做

轉場提案同時展示前一段退出與下一段接手的中途構圖：誰保持連續、誰退場、何時能閱讀下一段。核心圖形可以參與交接，但不強制所有區塊使用同一效果。導覽／資訊列收合時，說明原本占用的空間如何處理；反向捲動也須能恢復。

1. 交付以上資訊及可觀看的分鏡；原型尚未開始時明說。新方向不能用舊原型畫面假裝已呈現。
2. 記錄動態提案的版本、使用者確認的行為與未定項；視覺已確認但動態未確認時，不擴展完整首頁。
3. 動態確認後，轉入素材規格與核心片段試做。必要的獨立技術小實驗可先做，但不是使用者動態確認，也不取代分鏡。
4. 在瀏覽器實看動作、停留、回捲及減少動態，再交付使用者操作；實作自查與體驗確認分開。
5. 使用者明確授權跳過節點或自行選擇時遵守並記錄，不重問。一般細節修正不新增確認關卡。
