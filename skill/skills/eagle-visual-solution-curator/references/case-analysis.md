# 整體視覺方案｜案例拆解與 Eagle 輸出

## 觀察要留下什麼

先記使用者喜歡的具體位置與原話，再分析它如何成立。喜好、可見事實與 AI 轉用建議分開呈現。日常單筆以指定片段為主，不要求填滿以下所有分析面向。

依實際收藏範圍記錄，不要求每案填滿所有項目；不可觀察的寫限制，不補想像。

| 面向 | 要留下的可用依據 |
|---|---|
| 核心價值 | 最值得參考的設計決策，以及它對品牌、訊息或操作形成的效果 |
| 構圖與層級 | 版心／滿版、主體比例與位置、文字換行、圖文關係、疊層、裁切與視覺焦點；重要比例可記觀察值，不假稱精確 CSS |
| 視覺系統 | 字體對比、色彩用途、留白、裝飾語言如何貫穿；全頁密度與節奏如何變化 |
| 影像美術 | 主體、景別、光線、材質、去背／情境、圖片序列、文字留白；什麼素材條件才能成立 |
| 互動與敘事 | 哪個內容隨操作發生什麼變化、如何引導理解，而不只列淡入／視差等效果名稱 |
| 轉用條件 | 必須保留的關係、可替換的品牌資料、長文或素材不足時會失效的地方，以及手機／無障礙限制 |

### 互動觀察

每個真正有收藏價值的互動，記「位置 → 觸發 → 起始 → 過程 → 結束」，再補實測的反向、重進、鍵盤／觸控與手機。可附畫面／錄影時間點。沒有操作工具或只有截圖時寫「僅確認此靜態狀態，動態未驗證」。不要把原站未驗證的 reduced motion 寫成已支援。

案例分析不必提前完成施工參數。原站實際行為與本案未來應採用的替代方案分開；建議可寫「轉用時需補鍵盤等效操作」，不能改寫為原站已有。

### 避免只抄外觀

弱：「黑白精品風，大字配產品圖，滑動很有質感。」

可用的寫法（僅示意格式，不是任何真實網站的觀察）：「首屏以單一產品佔據主要高度，短標題沿產品輪廓留白，背景與材質反光形成明暗層次。轉用時應保留主體比例、文字避讓及低資訊密度；若替換成多行介紹或一般橫幅照片，這個構圖便不成立。」有實測互動才追加狀態，不從示例推論案例。

## 單筆待審核格式

先給可讀的 Eagle 提案，再補簡短審核資訊。備註可分短段，不為追求一段文字省略關鍵行為。

```text
名稱：既有名稱／【待編號】品牌－收藏範圍
方案：整體視覺方案
來源：實際網址；另列模板介紹或截圖來源（如有）
目標：資料庫／現有項目 ID（新案標尚未建立）

備註：
【適用方案】整體視覺方案。
【收藏理由】使用者喜歡的位置與原話／忠實摘要；未提供時不代寫成使用者意見。
【核心參考價值】具體手法與形成的效果。
【視覺與影像】構圖、文字、影像、留白與頁面節奏。
【互動】重要狀態與已觀察操作；無動態收藏目標可省略，無法驗證則說明。
【轉用條件】建議保留特徵、素材／內容條件、適用情境與限制。
【證據範圍】觀察日期、頁面／區塊、桌機／手機實看範圍；來源失效或只看靜態須保留。

資料夾：只列已確認存在的完整路徑
標籤：只列既有適用詞彙，以半形逗號分隔；無則寫無
寫入狀態：待審核，尚未修改 Eagle

收錄判斷：只有使用者要求篩選時填寫；已指定收藏則省略
分類依據：各分類的畫面或內容證據
待確認／建議擴充：與正式欄位分開
重複檢查：查過的範圍與結果；無資料則寫未檢查
```

限制若會影響日後理解，必須留在 Eagle 備註，不能只放對話尾端。例如手機未測、互動僅由影片觀察、只有商品介紹封面。信心高低描述證據可靠程度，不等於設計好壞。

日常輸出可合併視覺與核心價值，避免重複敘述。來源沒有完整可用畫面時依證據縮小結論；分類未連線確認時，分別列「分類／標籤建議（尚未比對現有庫）」與驗證狀態，不能假稱既有分類或已寫入。批次才需要逐筆審核清單；不替每個單筆增加冗長報告。

未來檢索依分類／標籤先縮小範圍，再讀備註確認適用條件；關鍵特徵應使用一致名稱，保留使用者描述中的辨識詞於收藏理由。既有同義標籤優先沿用，不因 AI 換用語就新增一套分類。

## 批次與既有項目

- 先列完整目標數與 ID／網址，逐筆對應，不能只分析前幾筆卻回報整批完成。
- 模板介紹與同一模板預覽先視為同一案例線索；不同收藏區塊不一定重複，提出合併建議但不直接刪除。
- 既有項目先保留原文，列擬改欄位與原因；沿用與本次無關的筆記、分類和資料來源。
- 批次審核列每筆實際提案，不用「套相同分類」略過視覺不同的案例。收尾交代已分析／待補／待審核數。
