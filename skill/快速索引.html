1｜從 0 開始製作案件

適合已有品牌資料與需求，需要 AI 提出視覺及互動方向的整體視覺案件。

準備： 案件資料夾、客戶簡介、網站目的、頁面需求、Logo／CIS、素材及參考。資料未齊先列缺口。

流程： 資料盤點 → 方向與視覺 → 動態提案 → 核心片段 → 完整首頁與內頁 → RWD → 客戶校稿。

入口： visual-solution-immersive-director。高效行銷新案使用該方案既有流程，不套用整體視覺流程。

使用 visual-solution-immersive-director，從 0 開始製作本案。
案件資料夾：（填完整路徑）
品牌、需求與素材：（填位置）
參考及用途：（填網址與要保留的特徵，沒有就寫沒有）
請先盤點資料，再依方向、視覺、動態、核心片段及完整首頁讓我確認。
桌機以 2560×1280 為基準；桌機內部確認後直接接續 RWD，完整檢查後才交客戶校稿。
請記錄工具分工與產圖方式。

完成結果： 符合品牌方向、可預覽與操作的網站，包含約定頁面及 RWD、已確認版本與待辦。

2｜Webtech2 首頁已完成，要依 Lin-EVO 新規範重切

直接提供 Webtech2 做好的網站作為基準。由 Lin-EVO 依最新規範重新切成視覺一模一樣的靜態 HTML 網站，再接續製作內頁。

準備： 完成網站網址、可取得的原始素材與字型、內頁清單及內容。登入限制或無法取得的素材請列缺口。

流程： 實看原網站 → Lin-EVO 重切首頁 → 同尺寸比對視覺與互動 → 內部確認 → 內頁 → RWD → 客戶校稿。

入口： Lin-EVO。這是依成品重切，不是匯出或格式轉換，也不重新發想首頁設計。

使用 Lin-EVO，依最新 Lin-EVO 規範重新切版本案首頁。
案件資料夾：（填完整路徑）
Webtech2 已完成網站：（填網址）
素材與字型：（填位置，未取得請列出缺口）
內頁需求與內容：（填位置）
請實看原網站，重新製作視覺一模一樣的靜態 HTML／SCSS／JavaScript。
保留構圖、字型、圖片、間距、裁切、導覽及動態，以相同尺寸比對，不自行改設計。
首頁重切確認後接續內頁；桌機完成後直接做 RWD，檢查完成才交客戶校稿。

完成結果： 依 Lin-EVO 新規範製作的靜態首頁與內頁、完整素材及互動，視覺比對與 RWD 檢查紀錄。

共用操作：素材、校稿與交付

3｜靜態首頁已完成，要接續內頁

已有可用的靜態首頁，沿用確認的視覺與工程，不重做首頁。

準備： 首頁程式與預覽入口、確認版本、共用 CSS／JS、內頁清單與文案素材。

流程： 讀首頁與共用元件 → 盤點頁型 → 代表內頁確認 → 延伸其他頁 → RWD → 客戶校稿。

入口： 一般切版用 Lin-EVO；整體視覺案件沿用 visual-solution-immersive-director，切版仍讀 Lin-EVO。

使用（填 Lin-EVO／visual-solution-immersive-director），接續本案內頁。
案件資料夾：（填完整路徑）
已確認首頁與預覽：（填版本及位置）
內頁清單與內容：（填位置）
請先讀首頁、共用樣式、互動與進度，保留已確認成果。
先盤點頁型，完成代表內頁給我確認後延伸其他頁。
各頁沿用共用導覽與頁尾；桌機完成後直接接續 RWD，檢查後再交客戶校稿。

完成結果： 與首頁一致的完整內頁、共用元件與必要互動，各頁可預覽並完成 RWD。

4｜高效行銷方案已有初版，交給設計師優化

接手既有高效行銷案件，針對初版的排版、圖片、閱讀層級及操作品質優化。

準備： 原案進度與規格、確認母版、初版網站、客供素材、需改善的頁面與範圍。

流程： 讀原案 → 實看全頁 → 列出具體改善 → 修正 → RWD 檢查 → 客戶校稿。

入口： 沿用高效方案流程，使用 Lin-EVO 執行切版修正；不因優化重啟整體視覺提案或更換確認母版。

接續本案高效行銷方案，使用 Lin-EVO 優化已完成初版。
案件資料夾與進度：（填完整路徑）
目前初版與預覽：（填版本及位置）
優化範圍：（填頁面與重點）
請先讀原案規格、確認母版與現有成果，實看全頁並提出可執行的改善。
保留既有方案限制、功能與確認方向，不擴大為重新設計。
完成排版、素材與互動修正，同步檢查受影響的 RWD，再整理客戶校稿版。

完成結果： 在原案範圍內完成優化的版本，清楚列出改動、檢查結果及待確認項目。

5｜已有 Figma／設計稿，要開始切版

設計方向已定，依設計稿製作網站，不另做品牌提案。

流程： 讀設計稿 → Lin-EVO 切版 → 同尺寸比對 → 桌機內部確認 → RWD → 客戶校稿。

完成結果： 符合設計稿的靜態網站、RWD、必要互動與校稿紀錄。

6｜網站已完成，要修改內容或修正問題

處理客戶回饋、內容替換、版面與互動問題，保持其餘確認成果。

準備： 目前有效版本、頁面與區塊、回饋或操作步驟、對照截圖／錄影、新素材。

流程： 找原因 → 修改來源 → 檢查受影響頁面與 RWD → 回填紀錄 → 再次校稿。

入口： 靜態網站修正使用 Lin-EVO，沿用原案規格與確認成果。

使用 Lin-EVO，處理本次網站修改。

請先定位原因，再以最小必要修改處理，保留其餘確認的設計與功能。

上傳校稿版依本次授權執行。
