先看重點

一個入口，五次確認

整體視覺網站只用一支主 Skill。你不必先想好構圖、動畫或技術解法，AI 會主動推進，只在五個確認點停下來等你判斷。

  • 只有一個入口

    visual-solution-immersive-director 同時負責設計、素材、切版與自查，不分派角色，也不會自動開多個 AI 代理。

  • 你判斷，AI 製作

    你提供資料、做確認與取捨；整理資料、提案、做素材、實作、實看與修正都由 Skill 主動完成。

  • 2560×1280 桌機優先

    構圖、裁切、字級與捲動節奏都在這個尺寸驗收。本手冊包含 RWD：桌機內部確認後接續平板與手機，檢查完成才交客戶校稿。

  • 「好」只確認看到的

    靜態視覺通過不代表動態通過，片段通過也不代表整頁通過。

Eagle 資源庫操作

eagle

搜尋、資料夾與標籤操作，其他 Skill 需要時會讀。也可以直接請它搜尋 Eagle。

適合

  • 整體視覺網站：以客戶既有品牌內容為主體，做專屬構圖、影像整合與有目的的互動。
  • 忠實重建：指定的來源就是答案，逐項對照還原。
  • 指定特徵轉譯：只取參考網站的某個特徵，其餘原創。
  • 同案內頁：首頁確認後，延伸到內頁。

不適合

  • 高效方案案件：母版、流程與產圖管道都不同，請用高效方案的 Skill。
  • 一般切版或小幅 CSS 修改：使用 Lin-EVO／Lin-EVO，沿用案件既有結構。
  • 還沒有品牌母題的品牌賦能案：先完成品牌概念與專屬素材，再回來做網站。

流程與確認點

你只要顧這 5 個確認點

Skill 依序推進，只在琥珀色的確認點停下來等你。忠實重建的案子跳過方向確認，視覺與動態提案改成來源對照與還原分鏡。

  1. 01人工開案

    提供案件資料夾、客戶資料、CIS 與素材。

  2. 02Skill盤點與模式判斷

    分開事實、推論與缺口，決定原創、特徵轉譯或忠實重建。

  3. 03Skill提 2–3 個方向

    概念真正不同，附評分與推薦。

  4. 04人工① 方向確認

    選定一個，或授權 AI 依推薦代選。

  5. 05Skill視覺提案

    用色比例、字體、ICON、人物與 2560×1280 關鍵構圖。

  6. 06人工② 視覺確認

    確認視覺，不等於確認動態。

  7. 07Skill動態提案與分鏡

    起始、過程、結束，轉場與回捲。

  8. 08人工③ 動態確認

    先看分鏡，確認後才進實作。

  9. 09Skill核心片段試做

    素材、規格與可操作預覽，在 2560×1280 自查。

  10. 10人工④ 核心片段確認

    實際捲動與操作，不是看截圖。

  11. 11Skill完整桌機首頁

    全頁內容、動態節奏、Nav、Footer 與 CTA，自查到頁尾。

  12. 12人工⑤ 完整首頁確認

    整頁一次確認。

  13. 13人工提出內頁

    代表頁先確認，再展開同類頁。

  14. 14人工接續 RWD

    桌機內部確認後製作，檢查完成才交客戶校稿。

人工確認點Skill 自動推進後續製作階段

開案時 Skill 會先問你是否授權 Codex 執行已定規格，以及產圖方式，答案記在進度檔。核心片段確認後，若已授權且場景表、規格與素材齊全，完整首頁與內頁的實作可交給 Codex，Claude 做最後實看。產圖預設由 Claude 操作 ChatGPT 網頁生成、你下載成品，不用 Codex 產圖。這是建議分工，不是強制。

確認與回饋

你說「好」的時候，確認了什麼

每個確認點分開記錄版本與範圍。回「好」只會讓當下展示、而且你明確確認的內容變成已確認。

  1. 01五個確認點分開算

    方向、視覺、動態、核心片段、完整首頁各自記錄版本與範圍。

  2. 02只涵蓋當下展示的

    還沒展示過的結果不算確認；靜態視覺不代表動態，片段不代表整頁。

  3. 03中間不會一直問你

    素材處理、細節、程式修正與重新檢查，會在已授權範圍內連續做完。

  4. 04回饋先寫回正本

    像「人物不要拆」這類回饋會變成素材約定，寫進正本後才實作，不會只留在對話裡。

  5. 05三種狀態分開記

    AI 自查通過、AI 自評、你的確認是三件事；分數不代表完成。

  6. 06做不出來就修到成立

    不會包裝成「完成，之後可優化」。同一原因修兩輪沒改善就換做法；要改已確認方向時，會帶方案來問你。

回饋怎麼給

講清楚三件事，能附參考或數值更好。

哪裡位置或區塊例：A 到 B 的換層
看到什麼實際的問題例：要捲很久才換，感覺黏住
想要什麼期望的結果例：縮短到一個畫面內換完

合起來說：A 到 B 的換層要捲很久才換，感覺黏住，縮短到一個畫面內換完。

實測案例學到的說法

品牌個性抓不到，例如不夠可愛

直接給字體與參考網站當基準；品牌個性很難讓 AI 自己判斷。

區塊之間太平、沒有重點

提供 CIS 輔助圖形的應用頁當參考，要求區塊之間加上銜接。

編排重複，好幾段都是左文右圖

指出哪幾段重複，要求每段有自己的構圖邏輯。

參考網站的風格被整套搬過來

說清楚只取哪一部分，例如「只取版面節奏，不取字體」。

動態幅度看不出來

在 2560 寬實看後給數值，例如位移從 28px 加大到 72px。

捲動換層太黏或太快

實際捲過後指出位置與感受，例如「A 到 B 要捲太久才換」。

常見問題

開始之前，大家最常問的

沒有 CIS 可以開始嗎？

可以。Skill 會盤點 Logo、產品、官網與照片裡的品牌線索，針對缺的部分提出具體建議與樣張，經你確認後作為本案網站視覺約定。

為什麼先看 2560×1280？

這是第一階段的驗收尺寸，構圖、裁切、字級、捲動距離與效能都在這個尺寸實看。桌機內部確認後接續 RWD，完成檢查才交客戶校稿；本案需要其他桌機尺寸時可以直接指定。

可以不做片段，直接要完整首頁嗎？

可以明確要求。Skill 會先完成全頁構圖、素材與動態強弱的規劃再實作，不會只做 Banner。

可以沿用高效方案的母版或案例嗎？

不能直接沿用。高效方案的母版策略、產圖管道、案例結論與額度換算都不適用，歷史案例只供查閱。

會自動叫 Codex 或開多個 AI 代理嗎？

不會自動叫。每個案件開始時 Skill 會先問你要不要授權 Codex 執行已定規格，以及產圖方式，答案記在進度檔，之後不重問；沒授權就全部由 Claude 做。建議的分工是：Claude 負責到核心片段確認的設計工作與之後每一輪的實看；核心片段確認後，場景表、規格與素材齊全時，可交給 Codex 執行完整首頁與內頁，Claude 只做最後實看。產圖不走 Codex：由 Claude 操作 ChatGPT 網頁生成、你下載成品。

工具授權或設定有問題怎麼辦？

把出現的訊息交給維護者，核對目前工具與案件設定。安裝與更新方式見 INSTALL.md，案件內的設定依現有規範處理。

換電腦或換模型要注意什麼？

先請 Skill 更新 experience-status.md：目前階段、已確認與未確認項目、不可改的內容、素材與預覽路徑、動態規格、已知問題和下一步。接手時說「繼續這個案件」即可；換電腦時等雲端硬碟同步完成再開始。

覺得不對，但說不出哪裡不對？

請它「先自查，列出目前最弱的三處並修正」，再從修正結果往下討論。
