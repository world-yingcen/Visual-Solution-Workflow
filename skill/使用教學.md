## 先選使用環境與 Skill

先依使用環境選入口。Claude 網頁／App 上傳 ZIP；Claude Code／Codex 使用本機 Git 安裝。兩種環境的整體視覺入口名稱不同，Lin-EVO 與 Miffy-EVO 名稱相同。

- Claude 網頁／App：上傳並啟用 Visual-Solution-Workflow 與 Lin-EVO；要轉 EVO 時另啟用 Miffy-EVO。GSAP 按需分別上傳，workflow 包不內附這些 Skill。
- 先說「使用 Visual-Solution-Workflow，討論本案視覺與動態方向」；方向確認後說「使用 Lin-EVO，依已確認設計切版」；靜態版確認後再說「使用 Miffy-EVO，轉成 EVO 匯入成果」。
- Claude Code／Codex：整體視覺入口仍為 visual-solution-immersive-director；切版用 Lin-EVO，轉換用 Miffy-EVO。由 AI 檢查已確認來源並安裝本輪缺少的相關 Skill。
- 本機 Git 來源每輪先安全更新；上傳的 ZIP 是快照，不會自動更新。規範更新後重新上傳，停用舊名稱／舊版本，避免同時啟用兩份。
- 網頁／App 請提供案件檔案或工具可存取的來源；不能假設能讀本機 /Users、Google Drive 同步資料夾、localhost、公司內網或 Eagle。缺能力時列出未驗證範圍。

## 第一次使用｜從沒有安裝任何工具開始

本節適用 Claude Code／Codex 本機環境，假設你還沒安裝 AI 工具，也沒有任何 Skill。先完成下面三個階段，再開始案件；此時不需要先會寫程式，也不用先準備整套工程環境。

### A｜準備帳號與使用權限

先向 維護者確認公司指定的工具、帳號與可使用權限：

- **Claude 帳號**：需要能使用 Claude Code，之後才可操作本機檔案與製作網站。
- **ChatGPT 帳號**：本案使用 Codex 或 ChatGPT 產圖時準備。
- **GitHub 帳號**：把帳號名稱提供給維護者，請他加入公司私人 Skill repo 的協作者，並接受邀請。

還沒有帳號或不確定公司用哪個方案，先請維護者協助，不必自行購買。登入與帳號授權由你本人操作。

### B｜安裝 Skill 與必要工具

Skill 是 AI 的工作規則，和 AI 軟體分開安裝。所需入口如下：

- **整體視覺主 Skill**：從品牌資料開始提案及製作整體視覺網站。
- **Lin-EVO**：共用切版與校稿規範。
- **Miffy-EVO**：已確認靜態版轉成 EVO 匯入成果，需要轉換時使用。

AI 工具已能使用後，才把下面這段貼進目前使用的本機工作。Git（取得及管理檔案的工具）與 Python（執行安裝程式的工具）由 AI 先檢查，缺少時協助準備；需要電腦管理者密碼或公司權限時找維護者處理。

**貼給已安裝的 AI：**

```text
這台電腦是第一次設定，尚未安裝網站製作的 Skill。
目前使用工具：（填 Claude Code／Codex）。
請先檢查本機 Git、Python 與 GitHub 存取權限，協助準備必要工具。
整體視覺來源：https://github.com/world-yingcen/Visual-Solution-Workflow
Lin-EVO 來源：https://github.com/world-yingcen/lin-skill
請先讀這兩份來源的安裝文件，安裝本工具需要的整體視覺主 Skill 與完整 Lin-EVO。
來源庫放在固定本機位置，不放雲端同步資料夾；只安裝到目前工具對應的 Skills 位置。
Claude Code 的整體視覺優先使用 Plugin；依文件採另一種方式時，同一工具不要重複安裝兩份。
若尚無私人 repo 權限，請列出需要維護者協助的項目。
需要登入或授權時讓我本人操作，不在對話中索取密碼。
目前只設定工具與 Skill，不開始製作網站、不推送或部署。
```

Claude Code 與 Codex 都要使用的人，各自在對應工具完成一次安裝；在其中一個工具裝好，不代表另一個也能讀到。維護者的詳細操作見 [安裝文件](INSTALL.md)。

### C｜重新開啟並驗證，再開始案件

安裝完成後重新開啟目前使用的 AI 工具，開啟目前的本機工作，再貼下面這段：

```text
請確認本工具可使用 visual-solution-immersive-director 與 Lin-EVO，並重新讀取規範。
請回報實際安裝位置、使用版本與缺少的項目，確認能讀取目前本機資料夾。
先不要開始製作網站。安裝或更新未完成的部分請如實標示，整理可執行的處理方式。
```

**做到這裡再往下：** AI 已讀到本案所需的 Skill，也能讀取本機資料夾。若失敗，把錯誤畫面與回覆交給維護者；完成後再開啟真正的案件資料夾，進入第 1 步。

### 需要 ChatGPT 產圖時，再設定 Chrome

依本案選定的產圖方式準備。採用「Claude 操作 ChatGPT 網頁、你下載成品」時：先從 [Chrome 官方下載頁](https://www.google.com/chrome/)安裝瀏覽器，再依 [Claude in Chrome 官方設定說明](https://code.claude.com/docs/en/chrome)安裝與連接擴充功能，並由你本人在 Chrome 登入 ChatGPT。連接後請 Claude 確認能讀取指定分頁；此時只驗證連線，不產圖。

若本案使用其他影像工具，依指定方式設定並記入進度，不必為此額外啟用 Chrome 產圖管道。Eagle 與網站編譯工具則在需要的製作階段再核對，不要求第一次就全部安裝。

## 第 1 步｜準備並開啟案件資料夾

每輪開始工作前，AI 會先檢查 Skill 來源與案件工作資料夾是否由 Git 管理；有 Git 就先安全更新，再讀規範與進度。連結安裝不必重新複製。若有未提交修改、版本分歧或無法連線，會保留檔案、說明未完成更新，再繼續不受影響的工作。

### A｜將專案檔案放到自己的 Google Drive

請將專案提供給你的檔案，複製到**自己的 Google Drive 案件資料夾**，請勿直接在共用區執行。

使用電腦上可存取的 Google Drive 同步資料夾，等檔案同步完成後，再用 AI 工具開啟這份案件資料夾。

### B｜確認 PDF 讀取方式

PDF 可以保留。Skill 會先列出案件資料夾及子資料夾中的 PDF 並檢查大小，未超過 10 MB 才在讀取內容前詢問：「這些 PDF 需要讓 AI 現在先讀嗎？還是有要用到再讀？」

單一 PDF 超過 10 MB（10,000,000 bytes），AI 一律拒絕讀取，即使你要求也不例外。請直接截圖提供需要的重點，或將重點整理成 Markdown（.md）檔案提供；原檔保留並標記未讀取。

為避免不必要的 token 消耗，選擇用到再讀的 PDF 會先集中到 `04_型錄與原始素材/PDF_待用時讀取/`，並標記尚未讀取；後續需要時只讀相關檔案或頁面。

### C｜請 Skill 整理資料夾

檔案已放到自己的 Google Drive 後，請本案適用的 Skill 盤點並整理資料夾。你不需要先自行重新命名或分類。

**貼給 AI：**

```text
使用本案適用的 Skill，幫我整理案件資料夾。
案件位置：（填自己的 Google Drive 在本機的案件資料夾完整路徑）。
我已將專案提供的檔案放好；請勿操作共用區的原始檔案。
遇到 PDF 請先檢查大小，單一檔案超過 10 MB 一律拒絕讀取；未超過上限才詢問要現在先讀，還是有要用到再讀；選擇用到再讀的 PDF 請整理到獨立資料夾並標記尚未讀取。
請先讀取資料與既有進度，再依本案規範整理資料夾、素材、文件及目前工作入口。
保留既有網站的資源引用與已確認成果，列出整理結果及缺少的資料。
本輪先整理資料，不開始設計或切版。
```

### 整理後的資料夾會像這樣

需求、品牌素材、頁面資料與待確認事項分開放；先看 README.md，就能找到目前的工作入口。

```text
自己的 Google Drive／案件名稱/
├── README.md                     案件說明、目前入口與預覽方式
├── 01_專案需求與規劃/            需求、架構、視覺與動態提案
├── 02_品牌素材/                  Logo、CIS、字型與共用素材
├── 03_頁面製作素材/              各頁面的文案、圖像及製作資料
│   ├── 03_01_首頁/               首頁各區塊資料
│   └── 03_02_關於我們/           依本案頁面清單延伸
├── 04_型錄與原始素材/            客供型錄、原始圖片與影片
│   └── PDF_待用時讀取/           已選擇用到再讀、尚未讀取的 PDF
├── 05_待確認與交接/              進度、待確認事項與交付資料
│   └── experience-status.md      目前進度；已有進度檔就沿用
└── 99_歸檔/                     需要保留的舊提案與試作
```

這是整理後的示意。實際資料夾依案件內容與既有工程調整；Skill 會說明整理結果，不為配合示意重建已有網站。

**做到這裡再往下：** 檔案位於自己的 Google Drive 案件資料夾，PDF 的讀取方式與暫存位置已確認，Skill 已完成整理並說明資料位置與缺口。

## 第 2 步｜開始案件並確認工具分工

預設建議由 Claude 主導設計與每輪驗收；核心片段確認、整頁規格與素材齊全後，可由已授權的 Codex 執行完整首頁、內頁與細修。這是建議分工；若你只使用一個工具，直接告訴 AI，由目前可用工具推進並說明能力缺口。

同案授權記入進度，之後沿用。需要切換工具時，先請目前的 AI 記錄確認內容與下一步，再讓接手工具讀取，不必自己搬運整段對話。

參考用途請選清楚：**忠實重建**是沿用約定的版面及動態；**指定特徵轉譯**是保留喜歡的特徵、重新設計；**原創方向**是以本案品牌發想，參考只校準品質。

**貼給 AI：**

```text
使用 visual-solution-immersive-director，開始這個案件。
案件資料夾：（填完整路徑）
客戶／品牌：（填名稱）
設計稿與參考：（填連結或位置，沒有就寫沒有）
參考用途：（忠實重建／指定特徵轉譯／原創方向）
想保留的參考特徵：（填具體區塊或效果，沒有就寫沒有）
工程師範本資料：（填位置，未取得就寫尚未取得）
Codex 執行已定規格：（授權／本案不使用）
產圖方式：（預設 Claude 操作 ChatGPT 網頁、我下載成品／填其他指定方式）
先做 2560×1280 桌機首頁；桌機內部確認後直接完成 RWD，再交客戶校稿。
請依方向、視覺、動態、核心片段、完整首頁的順序讓我確認。
請讀既有進度，將本案範圍、工具授權與產圖方式記錄下來。
```

**做到這裡再往下：** AI 說明本案流程、工具分工與缺少資料。

## 素材與產圖｜需要時在這裡配合

AI 應先盤點客供素材，再提出缺少圖片的用途與構圖。正式 Logo、產品、角色及 IP 使用客供原檔，不用生成近似版。

預設產圖由 Claude 透過 Claude in Chrome 操作你已登入 ChatGPT 的 Chrome 網頁；你再下載成品到指定位置。先請維護者確認擴充功能與登入狀態。若無此工具或本案指定其他產圖方式，讓 AI 記錄替代方式及需要你配合的步驟。

每張圖先確認用途、主體位置、文字留白、比例與檔名。下載時照指定檔名存到案件素材資料夾，再告訴 AI 已放好；AI 實看並提出需要調整的地方；轉檔／壓縮由你自行處理，提供完成檔後再置入。不要只貼預覽縮圖當正式成品。

**貼給 AI：**

```text
請先列出本輪需要的圖片，以及可以沿用的客供素材。
缺圖請給我可以看的構圖建議，說明用途、比例、文字留白、檔名與存放位置。
依本案已記錄的產圖方式執行，需要我下載時逐張告訴我。
成品放好後請實看，檢查是否適合版面；列出需要我自行轉檔／壓縮的項目，提供完成檔後再置入。
```

**做到這裡再往下：** 圖片用途與風格符合方向；正式素材、生成素材與暫代圖已區分，檔案能在案件資料夾找到。

## 第 3 步｜確認設計方向

原創案件由 AI 提出 2–3 個概念不同的方向，說明適合的原因與推薦。看它是否符合品牌、客群與網站目的；忠實重建則先確認保留與可替換範圍，沿用約定參考。

**貼給 AI：**

```text
我選擇方向：（填名稱）。
想保留：（填喜歡的部分）。
需要調整：（填不適合的部分）。
請記錄確認方向，再準備視覺提案。
```

**做到這裡再往下：** 方向與參考使用邊界已清楚。沒有 CIS 時，AI 提出的色彩、字型等建議需經你確認，才能作為本案網站的視覺約定。

## 第 4 步｜確認視覺提案

看實際構圖、色彩比例、字體、圖示、背景圖騰、形象圖片與功能圖解，以及它們怎麼用在主要區塊。AI 應提供可觀看的畫面，不能只有風格形容詞或色碼清單。

確認基準是 **2560×1280 的瀏覽器內容區域**。你的螢幕較小時，請 AI 提供該尺寸截圖或對應預覽，自己再看可操作版本；縮小截圖不代表已驗證小螢幕版。

## 第 5 步｜確認動態提案

AI 用分鏡展示主要區塊的開始、過程與結束，說明往下捲動、往回捲動、點擊時會看到什麼，以及文字停留與閱讀時機。全頁要有強弱節奏，不能只設計首屏。

```text

## 切版與校稿｜這次新增的共同檢查

這裡是操作提醒；詳細工程規則由 Lin-EVO 維護，不在教學另放一份系統程式。

### 頁面與 SEO

每案有搜尋結果頁；每個完整頁面只有一個 h1，h2～h6 依內容層級排列。只有 Navi 使用 header 標籤。逐頁核對 title、描述、圖片 alt、連結及圖片尺寸；正式網址、索引與後台資料交工程師確認。

### 詢問車與搜尋頁

公版 CSS 可依案件確認需求調整，公版 HTML／JS 不改。搜尋頁未指定調整時忠實沿用參考，標題、摘要與按鈕都要核對實際樣式。

### 產品頁與分類選單

產品頁可新增 .inquiry-group，將加入詢問單放在購買按鈕群下方、商品資訊底部，保留原生綁定。分類選單沿用 left_menu001，桌機保留案件外觀，手機下拉邏輯是公版；分類文字導頁、箭頭獨立展開、顯示目前分類，清單不得被遮住。

### 案件設定

購買按鈕隱藏依頁面與實際用途判斷，包含手機版本；不誤隱藏其他功能。1199px、18px 箭頭、container-75、字級倍率及配色是案件確認值，不強制所有網站使用。案件選單差異集中在 _left-menu.scss 或既有同用途檔案，於公版 CSS 後載入。

### 動態與套件

一般模式播放確認過的動畫；減少動態模式仍完整呈現內容與操作。GSAP pin／scrub 要有正常閱讀的替代布局，不能只停動畫而留下空白或疊層。EVO 套件沿用平台版本與載入方式，不自行加 CDN；Swiper／GLightbox 用 data-vendor，Lenis 需先確認本案系統已更新開放，GSAP／AOS 由編輯器工具列開啟。

### 圖片與容量

切版後檢核專案檔案大小，AI 列出非 WebP／SVG 圖片的路徑與大小，由使用者自行轉檔／壓縮。WebP／SVG 也要看實際容量，AI 不代做圖片轉檔。

### Demo 與交接

依使用者要求可獨立模擬加入、數量、移除及表單，不真的寄出詢問。正式接入前排除 Demo 程式及示範資料，只保留原生系統處理器；有產頁腳本就同步更新。每次切版／功能修改同步唯一的工程師交接說明.md，列已完成、待接入、未實測及公版待修項目。

| 預覽打不開 | 貼網址、錯誤畫面及剛才操作，請 AI 檢查啟動與資源路徑 |
| 版面或動畫不對 | 附頁面、區塊、尺寸、截圖或錄影，說明預期及實際結果 |
| 素材生成後不知道存哪 | 請 AI 逐張提供檔名與案件內存放位置 |
| 工程庫或內網指南無法讀取 | 確認公司網路／VPN，請 AI 說明可繼續與受阻部分 |

發生問題的頁面／區塊：（填位置）。

實際：（填發生的情況，附截圖或錄影）。
使用的預覽／站台與尺寸：（填已知資訊）。
請先找原因，修正已授權範圍並重新驗證，保留其他已確認內容。
如果目前無法處理，請整理缺口、影響及可執行方案給維護者或工程師。
```
