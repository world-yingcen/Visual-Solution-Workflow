# LIN 切版｜設計師操作教學

更新：2026-10-09 · 零程式基礎版

適合已有 Figma／設計稿，要請 AI 做成網站或修改既有頁面的案件。你不用會寫程式，也不用先學範本名稱。

## 第一次使用｜請 LIN 協助設定

告訴 LIN／維護者你使用 Codex 還是 Claude Code，請他協助安裝 lin-frontend。重新開啟 AI 工具後，貼：「請確認可以使用 lin-frontend，並已讀到規範。」找不到時把回覆交給 LIN。

## 第 1 步｜準備資料

開啟本案資料夾，提供設計稿、圖片、文案，以及這次要做哪些頁面、是否包含平板與手機。要轉 EVO 的案件，請提供工程師給的範本資料位置；沒有就請工程師提供，不用自己研究內容。

## 第 2 步｜貼這段開始

```text
使用 lin-frontend，依本案設計稿製作網站。
設計稿：（填連結或檔案位置）
素材與文案：（填位置）
本次頁面：（填頁面名稱）
製作尺寸：（填設計稿尺寸；是否包含平板與手機）
工程師的範本資料：（填位置，未取得就寫尚未取得）
切版時一起做好 EVO 可編輯的內容結構，仍提供完整網站校稿；客戶確認後交工程師匯入與檢查。
請先讀現有進度，沿用已完成的部分，不要重新開始。
程式規範與檔案整理請自行處理；需求不確定時一題一題問我。
```

AI 應說明這次製作範圍與缺少資料。這個流程不要求先做品牌提案，也不固定桌機尺寸。

## 第 3 步｜打開預覽看結果

貼給 AI：

```text
請自行檢查完成的頁面，再幫我開啟預覽。
告訴我要看哪些頁面、試哪些操作，以及還有什麼沒完成。
第一次製作也請一起準備 Cookie 提示與隱私權政策頁。
```

對照設計稿看字體、圖片、留白與排列；自己點選單、按鈕及輪播。有包含平板、手機，就一起檢查對應畫面。政策是草稿時請客戶確認內容。

## 第 4 步｜指出要改哪裡

附上頁面名稱、區塊位置與截圖，不需要猜程式原因。

```text
關於我們第二區的標題太靠近圖片，請依這張設計稿調整。
只改這個範圍，保留其他已確認的畫面與動態。
改好後請重新開啟預覽給我。
```

看過修改結果再確認。客戶需要自行更換的文字、圖片與清單由 AI 先判斷，不確定用途時再回答即可。

## 第 5 步｜給客戶校稿

請 AI 整理這次可看的版本、查看方式與待補內容。需要上傳時先確認位置與權限。將客戶回饋集中提供，確認後記錄版本，不把 AI 自查當成客戶同意。

## 第 6 步｜交給工程師

```text
客戶已確認這一版，請整理給工程師的交付資料。
列出每頁的檔案、互動效果、客戶可編輯內容與待確認項目。
檢查缺圖、連結、每頁是否完整及本案約定的裝置尺寸。
分開標示：AI 已檢查、客戶已確認、工程師待匯入／接入、後台編輯與發布待驗證。
先不要自行打包、上傳或部署。
```

你不用手填程式對照表。AI 在切版時就完成已確認可支援的逐筆編輯結構；工程師處理匯入與必要串接，再測試修改、增刪、排序、儲存及發布。靜態預覽通過不等於後台已完成。

## 下次繼續

回到同一案件資料夾，貼：

```text
使用 lin-frontend，先讀本案進度，不要重新開始。
這次要做：（填工作內容）。
請保留已確認的設計與動態，用白話告訴我需要做什麼。
```

---

以下只給維護人員，設計師不用閱讀：

- 工作規範：[lin-frontend/SKILL.md](lin-frontend/SKILL.md)。
- 安裝程式：[install.py](install.py)。Codex 使用 `--tool codex`，Claude Code 使用 `--tool claude`；先搭配 `--dry-run` 核對，再安裝。程式需要 Python 3，不覆蓋同名 Skill，既有版本需先核對、保留後再處理；沒有自動更新功能。
- 本包不含客戶素材、網站基底或工程師範本資料，也不含整體視覺提案流程。平台接入仍依工程師規格，未經實際轉檔不可宣稱已驗證。
